## 四、15 条最有价值划线
> 选取规则：N = min(round(划线数×0.25), 15)，本周 65 条 → 15 条。

1. **《AI-Agents-in-Depth-zh-CN》**（多 Agent 协作）
   > 多 Agent 系统设计的核心问题包括：上下文是共享还是隔离，以及采用对等协作、管理者编排还是去中心化拓扑。……好的协作不是暴露彼此的思考过程，而是约定清晰的接口、边界、权限和验收标准。
   - 心得：多 Agent 协作的关键不是共享思考过程，而是共享清晰接口：上下文隔离 + 结构化「移交包」交换，边界、权限、验收标准先于智能。暴露思考会膨胀上下文，约定接口才能规模化。
   - 行动启发：设计多 Agent 时先定义接口与验收标准。

2. **《AI-Agents-in-Depth-zh-CN》**（多 Agent 协作）
   > Andrej Karpathy 曾说，“你可以外包你的思考，但不能外包你的理解”。管理 Agent 就像管理技术员工，既不能越俎代庖，也不能放手不管。
   - 心得：用 Agent 不省理解：可以把执行外包，但判断力必须留在自己手里。不懂系统架构的人管 Agent，就像不会看代码的经理管程序员，只会 PUA 不会指导。
   - 行动启发：用 Agent 前先理解其架构与原理。

3. **《AI-Agents-in-Depth-zh-CN》**（多 Agent 协作）
   > Agent 的故障却天生是拜占庭式的——它很少径直停止运行，而是继续给出看似可信的错误结论，且错误不会主动声明自己是错误。
   - 心得：Agent 出错最危险的地方是它「看起来对」。它不会像普通程序那样崩溃报错，而是自信地给出错误答案。所以交叉验证、多数表决不是多余，而是对抗天生拜占庭故障的必需设计。
   - 行动启发：关键结论默认加交叉验证再采信。

4. **《AI-Agents-in-Depth-zh-CN》**（多 Agent 协作）
   > 提议者—审核者循环的最小不变量是：审核者读取独立证据，而不是只复述提议者的解释；退回时必须给出可定位的修复条件
   - 心得：审核的意义在于独立性：审核者必须看原始证据、不看提议者的思考过程，否则只是回声。退回要附可定位的修复条件，否则只是把球踢回去，无限循环。
   - 行动启发：评审结论时只看证据，退回必附修复点。

5. **《AI-Agents-in-Depth-zh-CN》**（Agent 的持续进化）
   > 事实和经验适合写成知识文档；可以用语言清楚表达的策略适合写入提示词或 Skill；可以精确执行的流程与约束适合写成程序；感知、语言风格和隐式策略等高维能力则必须进入模型参数。
   - 心得：一条经验该沉淀到哪里，先问它的性质：事实进文档、策略进提示词/Skill、流程进程序、高维能力进参数。放错层级，要么维护成本爆炸，要么根本无法表达。
   - 行动启发：沉淀经验前先判断属于哪一层再落。

6. **《AI-Agents-in-Depth-zh-CN》**（Agent 的持续进化）
   > 能够确定性执行的约束应该进入程序，而不是继续堆在 Prompt 里。Agent 可以提出代码提案，但“是否能发布”必须由模型外的测试、审计和回滚机制决定。
   - 心得：能确定的约束写成代码才可靠，堆在 Prompt 里只是软建议。发布权必须留在模型外的测试、审计、回滚机制里——让 Agent 提方案，让系统做裁决。
   - 行动启发：确定性的规则写进程序，发布权留在模型外。

7. **《AI-Agents-in-Depth-zh-CN》**（Agent 的持续进化）
   > 生产系统中更稳妥的双循环结构：在线执行循环只完成任务并记录证据，不直接改写正式 Agent；离线进化循环聚合轨迹、诊断根因、生成更新提案，再通过验证门槛发布新版本。
   - 心得：让在线系统边跑边改自己很危险。稳妥做法是双循环：在线只执行+留证据，离线再诊断、提更新、过验证门槛后发布。执行与进化分离，才敢让 Agent 自我改进。
   - 行动启发：自动化进化走「在线执行+离线验证发布」双循环。

8. **《深度学习入门：基于Python的理论与实现》**（3.2 激活函数）
   > 神经网络的激活函数必须使用非线性函数。换句话说，激活函数不能使用线性函数。为什么不能使用线性函数呢？因为使用线性函数的话，加深神经网络的层数就没有意义了
   - 心得：非线性是神经网络的灵魂：若激活函数是线性的，再深的网络也只是线性变换的堆叠，等效于单层，深度就白加了。这是理解深度学习为什么「深」的第一块基石。
   - 行动启发：理解「深度」先搞懂非线性激活的意义。

9. **《深度学习入门：基于Python的理论与实现》**（3.2 激活函数）
   > sigmoid函数是一条平滑的曲线，输出随着输入发生连续性的变化。……sigmoid函数的平滑性对神经网络的学习具有重要意义。
   - 心得：从阶跃到 sigmoid 的关键不是形状，而是「平滑」：输出随输入连续变化，误差才能反向传播、梯度才有意义。平滑性让网络从「会分类」变成「能学习」。
   - 行动启发：选激活函数时先看它是否可微平滑。

10. **《深度学习入门：基于Python的理论与实现》**（第 3 章 神经网络）
    > 神经网络的一个重要性质是它可以自动地从数据中学习到合适的权重参数。
    - 心得：与传统程序「人写规则」不同，神经网络的价值在于权重从数据中自动学出来。人不再逐个定参数，而是设计结构、准备数据、定义目标，让学习算法去调权重。
    - 行动启发：建模时把精力放在结构与数据而非手调参数。

11. **《AI-Infra-Book》**（前言）
    > 先按第一性原理算出硬件允许的上限，再看系统离上限还有多远。这个习惯贯穿了我后来的工作，也贯穿本书。
    - 心得：性能优化先算理论上限再动手：先问「硬件允许的最快是多少」，再量系统离上限多远，优化才有方向和终点。否则容易在错误的地方反复折腾。
    - 行动启发：做性能优化前先算硬件理论上限。

12. **《腾讯云开发者》**（公众号文章）
    > 现在管理对象要变：把目标管起来，把上下文管起来，把依赖管起来。……管理链从「人、任务、工期」，转变为「目标、上下文、依赖、证据链」。
    - 心得：AI 参与研发后，管理对象从「人、任务、工期」变成「目标、上下文、依赖、证据链」。因为产出是否可信要靠证据说话，交接要靠上下文和依赖对齐。
    - 行动启发：管理 AI 项目时抓目标、上下文、依赖、证据。

13. **《腾讯云开发者》**（公众号文章）
    > 在 AI 编程的过程中，人到底是什么？……其实本质上代码不是我写的，文档也不是我写的，是 AI 帮我写成的。但为什么它能写成？因为我喂给了它上下文，并且我给它做了目标确认和关键决策。
    - 心得：AI 编程时代人的价值从「写」转向「定」：喂对上下文、确认目标、做关键决策。代码是 AI 写的，但方向是人定的——这才是不可外包的部分。
    - 行动启发：用 AI 编程时专注定目标、喂上下文、做决策。

14. **《费曼思考法：像学习高手一样思考》**（开启你的探索之旅）
    > 其次，学习的本质是“主动”。不要再满足于被动地划线、记笔记和反复阅读。请勇敢地合上书本，用“以教为学”的方式，去主动地提取、重构和生成知识。
    - 心得：划线、笔记、反复阅读都是被动的舒适区。真正的学习发生在合上书本、主动提取和重构的那一刻——以教为学逼你把知识从脑子里拉出来，而非只是灌进去。
    - 行动启发：读完一章合上书，主动复述再对照。

15. **《费曼思考法：像学习高手一样思考》**（怀疑的价值）
    > 费曼最著名的原则之一就是：“第一条原则是，你绝不能欺骗自己——而你自己恰恰是最容易被欺骗的人。”
    - 心得：最容易被自己骗：看不懂却说「懂了」，没验证却说「应该没问题」。费曼的第一条原则是智识诚实——承认不知道、主动找反例，是学习与判断的底线。
    - 行动启发：下「我懂了」的结论前，先找反例检验。
