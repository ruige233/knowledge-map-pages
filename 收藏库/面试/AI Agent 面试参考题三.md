# AI Agent 面试参考题三

> 一句话定位：AI Agent 面试：FC、MCP 与 Skills 全解析

## 摘要

本文是 AI Agent 面试题库第三部分（第 38~66 题），围绕工具调用三件套：Function Calling 讲模型如何表达调用意图（声明、决策、执行、回传四步），MCP 把工具接入标准化（USB-C 接口，M×N 降为 M+N），Skills 把流程封装成按需加载的知识包（渐进式披露省 token）。后半聚焦工程实践：大规模工具集降幻觉、权限收口、报错/超时/熔断隔离、多工具编排八大模块与 Spring AI Alibaba 实现链路。

## 要点

- Function Calling 四步：声明、决策、执行、回传，模型只表达意图、不执行
- MCP 是标准化协议，把 M×N 私有集成降为 M+N，三大原语为工具/资源/提示
- Function Calling 管「说」，MCP 管「接」，Skill 管「怎么干」，三者层次不同
- Skills 靠渐进式披露省 token：常驻元数据→按需正文→按需资源
- 工具幻觉三形态：选错、编造、参数幻觉，靠缩候选+优化描述+强校验治理
- 权限在 MCP 层收口：最小权限、读写分离、HITL，Agent 权限=用户权限∩职责
- 故障处理：只重试幂等瞬时错误，分层超时可取消，熔断+隔离
- 多工具编排八大模块，编排逻辑放 Skill、执行治理放 Harness

## 提炼

> 一句话定位：AI Agent 面试：FC、MCP 与 Skills 全解析

### 分节提炼

- **01 工具调用总览**：覆盖题库第 38~66 题：Function Calling、MCP 与 Skills 三大主题；问答体：每题给原理、对比与工程实践
- **02 FC 原理与 Tool Use**：四步流程：声明→决策→执行→回传；模型只输出结构化调用意图，执行始终在 harness；description 是选对工具最关键信号
- **03 参数格式错误处理**：错误分四类：语法/类型/字段/语义；处理链路：结构化输出约束→schema 校验→修复重试→降级→兜底；校验必须在服务端，不能信任模型输出
- **04 MCP 是什么**：本题无独立作答，与 41 题合并；MCP 是 AI 应用的 USB-C 接口（见 41 题）
- **05 MCP 定义与作用**：MCP 是模型与外部工具/数据的开放标准协议；把 M×N 私有集成降为 M+N，避免重复造轮子；三大原语：工具、资源、提示模板
- **06 MCP 底层原理**：Host-Client-Server 三层，JSON-RPC 2.0 消息；传输：stdio 本地、Streamable HTTP 远程；传统注册是进程内函数，MCP 是跨进程服务
- **07 FC 与 MCP 区别**：FC 是模型能力，MCP 是通信协议；二者互补不替代，层次不同；MCP 是 FC 的供给侧标准化
- **08 MCP 通信方式**：stdio：零配置、本地、延迟最低；Streamable HTTP：可远程、可共享、可鉴权；SSE 已被 Streamable HTTP 统一
- **09 MCP Server 开发**：开发八步：能力面→契约→逻辑→协议→传输→鉴权→观测→测试；description 要写何时用、何时不用；工具要幂等、可超时、可重试
- **10 MCP 落地场景**：四类落地：企业系统、代码工程、数据知识、外部 SaaS；权限在 MCP 层统一收口，写操作 HITL
- **11 扩展与安全设计**：扩展性：分层、无状态、动态发现、注册中心；安全性：认证授权、最小权限、沙箱、审计；读写分离，高危操作二次确认
- **12 MCP 之前的协同**：无 MCP 前：FC 分发、私有 RPC、消息总线；MCP 标准化工具层，A2A 标准化协作层
- **13 MCP 是否过时**：MCP 未过时，进入基础设施期；热度降因协议胜出、变底座、上层接过热度；现实问题：供应链风险、token 成本、粒度重
- **14 A2A 与 MCP**：A2A 是 Agent 间协作协议，与 MCP 互补正交；Agent Card+Task 委派+状态订阅；结构化契约、状态机、幂等、上下文隔离
- **15 MCP 与 Skills**：MCP 是协议层，Skills 是认知流程层；Skill 是文件、按需加载、token 极低；MCP 给手，Skill 给手艺
- **16 四概念辨析**：Prompt=说，MCP=接，Skill=know-how，Subagent=分工；四者不同层，叠加成能力体系
- **17 三者边界**：FC 管说，MCP 管接，Skill 管怎么干；判断：可调用动作→工具，步骤规范→Skill
- **18 Skills 指什么**：本题与 55 题合并作答；Skill 是文件组织的可复用能力包（见 55 题）
- **19 Skill 定义与调用**：Skill=元数据+正文+附属资源；渐进式披露：元数据→正文→资源；description 决定 Skill 是否被选中
- **20 Skills 省 token**：省 token 核心是渐进式披露；30 能力：24000 常驻→约 2800 按需；不常驻、不重复、不浪费
- **21 Skill 与 Rule**：Rule 短、常驻、无条件红线；Skill 长、按需、场景化手册；有交叉时 Rule 优先
- **22 渐进式披露实现**：三层：常驻元数据→正文→附属资源；加载是模型自主决策而非路由写死；上下文稀缺、可扩展、准确率要求决定渐进披露
- **23 Skill 系统设计**：必需字段：name、description、version；正文：适用场景、步骤、判定标准、常见坑；系统层：注册发现、检索、权限、评测治理
- **24 上百 Skill 处理**：三级漏斗：分层→检索→渐进式披露；分层砍到 20~30，检索 Top-K 5~10；检索有漏召回，需兜底工具
- **25 降低工具幻觉**：幻觉三形态：选错、编造工具、参数幻觉；解法覆盖决策前、决策中、决策后
- **26 缩小候选集**：分层+检索把 200 候选降到 8，选对率数量级提升；工具分组降低单次决策难度
- **27 优化工具描述**：description 写何时用/何时不用/返回什么；枚举值列全、给示例值减少参数幻觉
- **28 模型能力手段**：few-shot 对边界情况有效；工具调用稳定性是选型硬指标；tool_choice/JSON Schema 强约束
- **29 校验与兜底**：工具名白名单是防编造工具最后闸；业务校验防不存在的 ID；失败带具体错误回给模型重试
- **30 系统层面**：无权限工具不出现在候选集；记录误选率、监控调用多样性
- **31 编排与工具归属**：编排逻辑放 Skill，执行治理放 Harness；工具统一由 MCP 平台提供；会被复用→上平台；仅自用→本地注册
- **32 Agent 权限分配**：默认拒绝、白名单授权、按职责挂载；读写分离，写操作 HITL；Agent 权限=用户权限∩职责
- **33 故障处理总纲**：三类故障分开：报错、超时、连续失败；失败要结构化反馈给模型
- **34 报错处理**：只重试幂等的瞬时错误；指数退避+抖动，最多 2~3 次
- **35 超时处理**：分层超时且必须可取消；写操作需幂等+查询确认补偿
- **36 熔断与隔离**：熔断器+半开探测恢复；Bulkhead 隔离线程池；熔断走降级链并告警
- **37 给模型的反馈**：结构化反馈：错误类型+可重试性+建议；失败次数纳入预算，K 次后换策略；失败 observation 不污染上下文
- **38 多工具编排**：八大模块：注册中心、选择器、装配器、校验、执行器、结果处理、编排、横切；四类编排：串行、并行扇出、条件分支、循环修正；结果处理是一等公民
- **39 Spring AI FC 实现**：@Tool/@ToolParam 反射生成 JSON Schema；ToolCallingManager：查找、反序列化、反射调用、包装异常；异常包装成 ToolResponseMessage 便于自修正

### 带走三句话

1. 模型只会「写字」不会执行——所有安全边界都建立在「执行在 harness」这一认知上。
2. MCP 是接能力，Skill 是组织能力：一个给「手」，一个给「手艺」，层次不同不冲突。
3. 降幻觉与保安全都靠收口：缩候选、强校验、最小权限、失败结构化反馈。
