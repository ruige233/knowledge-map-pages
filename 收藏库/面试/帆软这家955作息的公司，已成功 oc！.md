# 帆软这家955作息的公司，已成功 oc！

> 一句话定位：帆软 Java 后端校招面经：分布式锁、MySQL、Java 三大块考点复盘

## 摘要

帆软 Java 后端校招面经。先介绍背景：ToB 软件公司，955 无强制加班，研发岗多在成都、南京等二线城市，校招月薪 20k+、年薪约 30w。正文三大块：分布式部分对比 MySQL、ZooKeeper 与 Redis 锁实现，讲 CAP 与 Redlock 加锁流程和成功条件；MySQL 部分讲事务 ACID、redo/undo/binlog、EXPLAIN 与 type、范围查询加锁、索引场景；Java 部分讲线程池、AQS、CAS 与 Spring 事务不回滚原因。

## 要点

- 帆软为 ToB 软件公司，955 无强制加班，研发岗多在成都、南京等二线城市，校招月薪 20k+、年薪约 30w。
- 分布式锁除 Redisson 外，可用 MySQL for update 排他锁或 ZooKeeper 临时顺序节点实现。
- ZooKeeper 锁基于 ZAB 协议满足 CP 强一致但性能下降，Redis 是 AP 模型，本质是性能与一致性的取舍。
- Redlock 需至少 5 个独立 Redis 主节点，超过半数节点加锁成功且总耗时小于锁过期时间才算成功。
- InnoDB 事务中持久性靠 redo log、原子性靠 undo log、隔离性靠 MVCC 或锁，一致性由三者共同保证。
- EXPLAIN 的 type 扫描效率从低到高为 All、index、range、ref、eq_ref、const，应避免 Using filesort 与 Using temporary。
- 可重复读下范围查询加 next-key 锁，唯一索引会退化为记录锁或间隙锁，非唯一索引不退化。
- Spring 事务不回滚常见原因：非 public、try/catch 吞异常、内部方法调用、检查异常未配 rollbackFor、MyISAM 不支持事务。

## 提炼

> 一句话定位：帆软 Java 后端校招面经：分布式锁、MySQL、Java 三大块考点复盘

### 分节提炼

- **01 分布式锁与 CAP 原理**：分布式锁可用 MySQL for update 排他锁或 ZooKeeper 临时顺序节点实现。；ZooKeeper 锁满足 CP 强一致但性能低，Redis 是 AP，本质是性能与一致性取舍。；Redis 单节点锁缺点：超时难设置、主从异步复制导致不可靠。；Redlock 加锁需过半节点成功且总耗时小于锁过期时间。
- **02 MySQL 事务、锁与索引**：InnoDB 事务四特性分别由 redo log、undo log、MVCC/锁机制保证。；EXPLAIN 重点看 type：All 最差、const 最快，尽量用 range 及以上。；可重复读下范围查询加 next-key 锁，唯一索引会退化，非唯一索引不退化。；唯一性字段、WHERE/GROUP BY/ORDER BY 字段建索引；重复多、表小、频繁更新不建。
- **03 Java 并发与事务**：线程池提交任务：核心线程未满建线程，满则入队，队列满再增线程，达上限走丢弃策略。；AQS 核心是 state、FIFO 等待队列、协作类重写的获取/释放方法。；CAS 三大缺点：ABA 问题、自旋循环开销大、只能保证单共享变量原子性。；Spring 事务不回滚：非 public、try/catch、内部调用、检查异常、MyISAM。

### 带走三句话

1. 分布式锁选型看一致性与性能取舍：无强依赖 ZK 用 Redis 即可，追求可靠性用 Redlock 过半节点判定。
2. 排查慢 SQL 看 EXPLAIN 的 type、key、rows、extra，尽量到 range 及以上。
3. 面试 Java 并发要把 AQS 三件套讲清，并熟记 Spring 事务不回滚五类场景及解法。
