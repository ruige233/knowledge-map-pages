# 字节抖音电商一面，被虐的很惨！

> 一句话定位：字节抖音电商后端一面凉经，覆盖线程池、Redis、MQ、网络与手撕算法

## 摘要

这是一篇字节抖音电商后端秋招一面凉经，按 Java、Redis、MQ、网络、算法五部分。Java 讲线程池好处与参数，keepAliveTime 默认只对非核心线程生效，allowCoreThreadTimeOut(true) 可让核心线程超时销毁。Redis 讲为什么快、过期字典与删除策略、热 key 优化、zset 底层。MQ 讲削峰解耦与 RocketMQ 延时消息。网络讲输入 URL 到页面显示的流程及 HTTP/HTTPS 区别。算法题为 LeetCode 3 无重复字符的最长子串。

## 要点

- 线程池复用线程降低资源消耗、提高响应速度与可管理性。
- ThreadPoolExecutor 核心参数 corePoolSize、maximumPoolSize、workQueue 决定线程扩容与入队。
- keepAliveTime 默认只作用于非核心线程，allowCoreThreadTimeOut(true) 可让核心线程超时销毁。
- Redis 快在基于内存、Reactor 事件循环+IO 多路复用、优化数据结构与简单协议。
- Redis 用过期字典记录毫秒级过期时间戳，删除策略为定期删除+惰性删除结合。
- 热 key 会占满 CPU/带宽甚至打挂 Redis，可用读写分离、Redis Cluster、二级缓存优化。
- zset 元素小于 64 字节且个数小于 128 用 ziplist，超阈值转 dict+skiplist。
- RocketMQ 4.x 延时消息只有 18 个固定等级，5.0 用时间轮实现定时消息。

## 提炼

> 一句话定位：字节抖音电商后端一面凉经，覆盖线程池、Redis、MQ、网络与手撕算法

### 分节提炼

- **01 Java：线程池**：线程池三大好处：降低资源消耗、提高响应速度、提高可管理性；核心参数 corePoolSize、maximumPoolSize、workQueue 决定线程扩容与入队；allowCoreThreadTimeOut(true) 让核心线程受 keepAliveTime 控制
- **02 Redis：快与热 key**：快的原因：基于内存、Reactor 事件循环+IO 多路复用、优化数据结构、简单协议；过期字典保存毫秒时间戳，查询时 O(1) 判断，过期即删除返回 null；删除策略为定期删除+惰性删除结合，兼顾 CPU 与内存；热 key 优化：读写分离、Redis Cluster、二级缓存（Caffeine）
- **03 MQ：解耦与延时消息**：用 MQ 三大好处：异步处理提高性能、削峰/限流、降低耦合；生产者与消费者经消息队列解耦，新业务订阅消息即可扩展；RocketMQ 4.x 延时消息仅 18 个固定等级，5.0 基于时间轮实现定时消息
- **04 网络：地址到页面**：输入 URL 后：DNS 解析 IP→TCP 连接→发 HTTP 请求→服务器响应→解析渲染并加载资源；HTTP 默认 80 端口明文，HTTPS 默认 443 端口走 SSL/TLS 加密，更耗服务器资源；HTTPS 解决数据传输安全与浏览器对服务器信任两大问题
- **05 算法：手撕题目**：手撕题为 LeetCode 3 无重复字符的最长子串（中等难度）；面试中需手写实现该算法题，考察编码能力

### 带走三句话

1. keepAliveTime 只管非核心线程；销毁核心线程需 allowCoreThreadTimeOut(true)。
2. Redis 用过期字典+定期删除+惰性删除管理过期键；热 key 要靠读写分离、Cluster、二级缓存分散压力。
3. 字节面试底层问得很深：线程池、Redis、MQ、网络与手撕算法都要提前吃透原理。
