# 大模型岗面试，为什么追问两层就答不动了？RAG、多 Agent、Harness 八道题逐个复盘

> 一句话定位：大模型岗面试八题复盘：技术点只备一层，往下追问两层就露馅

## 摘要

本文复盘一场大模型岗面试：简历写金融文档 RAG 与 LangGraph 多 Agent，面试官只追项目，八道题都第一层能答、再往下两层就含糊，总评“做得较浅，更看重成长性”。丢分归三种模式：追问一层见底、数字没有配套材料、不肯放弃预设答案，即三个追问方向——为什么这么做、什么情况下不成立、怎么知道有效。逐题拆解：开场话术、PDF 表格解析、RAG 相对长上下文的理由、向量检索相对 ES 的优劣、RRF 与 Reranker、MRR 三份材料、场景题信号、Harness 与 State 校验。

## 要点

- 面试官只围绕简历两个项目追，不出八股题；三个追问方向是为什么这么做、什么情况下不成立、怎么知道有效。
- 开场用四句话打底：业务目标与用户、整条链路、自己负责的模块边界、成果带一个数和一个业务含义。
- PDF 表格解析满分靠对比（PyMuPDF/DeepDoc/MinerU）、取舍理由与工程折中；再深一层是无边框表格的版面分析本质。
- RAG 相对长上下文有四条理由：成本延迟、有效性随长度衰减、数据动态更新、权限过滤；二者并非二选一。
- 向量检索长在语义、短在精确性（专有名词、数字、否定、不可解释、更新成本、严格过滤），故混合检索必然。
- RRF 只用排名丢掉分数强度；Reranker 不能全量是计算量原因；标准配置 top50-100 进 Reranker、再取 top3-5。
- 简历每个数字要配三份材料：评测集、bad case 分桶归因、消融表；配不齐的数字不如不写。
- Harness 管循环控制/上下文组装/工具调度/状态检查点/错误升级/预算/观测；State 要 schema 化并写入校验。

## 提炼

> 一句话定位：大模型岗面试八题复盘：技术点只备一层，往下追问两层就露馅

### 分节提炼

- **01 全文**：八道题丢分归三种模式：追问一层见底、数字缺配套材料、不肯放弃预设答案。；混合检索必然；RRF 只用排名丢分数强度，Reranker 全量不可行，召回看 recall、重排看精度。；MRR 0.72→0.92 需配评测集、bad case 分桶归因、消融三份材料，测试集与调参集必须分离。；Harness 管七类职责与升级阶梯；State 要 schema 定义、约束解码、写入校验，语义错误靠下游前置断言。

### 带走三句话

1. 每个技术点往下备两层：能同时说清“选了 A”和“A 何时不如 B”。
2. 简历数字配齐评测集、归因分桶与消融表，配不齐的数字不如不写。
3. 场景题先停两秒确认前提，别听到熟悉关键词就启动预设答案。
