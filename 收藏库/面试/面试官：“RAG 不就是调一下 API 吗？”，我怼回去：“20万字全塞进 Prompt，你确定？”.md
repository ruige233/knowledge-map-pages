# 面试官：“RAG 不就是调一下 API 吗？”，我怼回去：“20万字全塞进 Prompt，你确定？”

> 一句话定位：RAG 面试入门：定义、原理、与传统搜索对比及优势局限

## 摘要

本文以面试被挂的经历切入，指出把 20 多万字文档直接塞进 Prompt 的“裸调 LLM”不可取，正确做法是 RAG。随后讲解 RAG：它是信息检索与生成式模型结合的框架，先检索相关上下文再生成答案，可解决知识时效、私有数据访问、准确性与可追溯性问题；常见用途覆盖客服、研发运维、医疗、法律、教育及企业助手。文中还给出索引与检索两阶段原理，对比其与传统搜索引擎的差异，并总结优势（知识时效、降幻觉、权限控制、领域适应）与局限（检索依赖、注意力稀释、首字延迟、工程复杂度、长文本成本）。

## 要点

- 直接调 API 把 20 多万字文档塞进 Prompt 是“裸调 LLM”，噪声片段会稀释注意力、干扰推理并浪费 Token
- RAG 是信息检索与生成式大模型相结合的框架，先检索相关知识再让模型基于检索结果生成答案
- RAG 主要解决三类挑战：知识时效性、私有数据访问、回答准确性与可追溯性（对抗幻觉）
- RAG 常见用途包括客服机器人、研发/运维 Copilot、医疗、法律、教育及企业内部助手等
- RAG 工作分索引（离线）与检索（在线）两阶段：清洗、分块、向量化、入库，再到查询向量化、相似检索、生成增强与输出
- 传统搜索是相关性排序器、返回文档列表；RAG 是信息综合器、直接给答案并附引文
- RAG 核心优势：知识更新低成本、降低幻觉可追溯、检索层 ACL 权限控制、领域适应强
- RAG 局限：检索质量依赖（GIGO）、注意力稀释、首字延迟（TTFT）、工程复杂度高、长文本 Token 成本高

## 提炼

> 一句话定位：RAG 面试入门：定义、原理、与传统搜索对比及优势局限

### 分节提炼

- **01 解决知识时效性**：预训练 LLM 的知识固化在训练数据截止时间点（Knowledge Cutoff）；RAG 通过动态检索外部知识源，为 LLM 提供实时知识补充；例如 GPT-4 的知识库可能截止于 2023 年 12 月
- **02 打通私有数据访问**：企业私有数据因数据安全和商业机密无法被公开 LLM 直接访问；RAG 只提取与问题相关的片段给 LLM，在不泄露全部数据的前提下作答
- **03 提升准确性与可追溯性**：LLM 会产生幻觉（Hallucination），即编造不符合事实的信息；RAG 提供有据可查的参考文本，强制回答基于检索到的事实，降低幻觉率；可展示引用原文，使答案来源可追溯、可验证

### 带走三句话

1. 别把全部文档直接塞进 Prompt：先用 RAG 检索相关片段，避免注意力稀释和 Token 浪费
2. RAG = 索引（清洗、分块、向量化、入库）+ 检索（查询向量化、相似检索、生成增强）
3. 选型看场景：找文件用传统搜索更快，要答案、要总结、要跨文档对比再用 RAG
