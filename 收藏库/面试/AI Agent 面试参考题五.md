# AI Agent 面试参考题五

> 一句话定位：多智能体协作与编排面试题精讲：15 题覆盖协作、通信、隔离、调度与平台架构

## 摘要

本文是 AI Agent 面试题库第五部分，覆盖第 88~102 题共 15 道多智能体协作与编排考点。核心：多 Agent 不是更强的单 Agent，而是“用组织换能力”，解决上下文装不下、职责隔离、任务并行三类结构约束。内容涵盖六种协作模式与选型决策树、结构化 JSON 通信、结论冲突处理、Markdown 双轨防漂移、三层隔离、中心化调度。最后讲效率评估与平台集成：效率分四维、同模型 A/B 与成本归一化；平台五层架构做“薄平台加插件化”，并梳理六大组成与 12 步执行链路。

## 要点

- 多 Agent 不是更强的单 Agent，而是“用组织换能力”，解决上下文装不下、职责隔离、任务并行三类结构约束。
- 六种协作模式：Router、Supervisor-Worker、Pipeline、Debate、P2P、分层混合；选型看上下文压力、可枚举性、并行收益、一致性与可观测。
- 子 Agent 通信推荐结构化 JSON 消息，协议十要素含任务契约、状态机、同步异步、超时心跳、幂等、错误契约与权限收窄。
- 主 Agent 选子 Agent 用“规则优先 + Function Calling 兜底”，description 写明能力边界与“何时不该选”，保留“都不选”与可回退。
- 结论冲突分事实性、判断性、信息不对称、错误四类，按权威数据源、依据置信度、仲裁、辩论、投票、HITL、保守策略处理。
- 结果回收靠结构化契约、大产物引用、摘要回传与校验；异步通信要幂等、死信队列、超时取消、重派与熔断。
- Markdown 传任务易漂移，用“给人看 + 给机器用”双轨，约束原文传递、拆分后立即校验、接收方复述确认。
- 隔离三层：上下文独立会话加引用、权限降级传递、存储命名空间加默认私有；调研类系统选中心化调度，平台做薄平台加插件化。

## 提炼

> 一句话定位：多智能体协作与编排面试题精讲：15 题覆盖协作、通信、隔离、调度与平台架构

### 分节提炼

- **01 多智能体协作与编排**：覆盖第 88~102 题，共 15 道题，主题是多智能体协作与编排；题目来源多为阿里、美团、京东、字节、腾讯、蔚来等大厂
- **02 协作模式与优势**：多 Agent 是“用组织换能力”，解决上下文装不下、职责隔离、任务并行三类约束；六种协作模式：Router、Supervisor、Pipeline、Debate、P2P、分层混合；本质优势是上下文隔离与并行；上下文装得下、需强一致、缺可观测时不该上多 Agent
- **03 多 Agent 选型决策树**：选型决策树五问：上下文装得下吗、子任务强依赖吗、可枚举吗、需多视角吗、要并行吗；五个依据：上下文压力、可枚举性、并行收益、一致性与错误代价、观测与调试能力；落地：从单 Agent 起步，遇上下文墙才拆，首选 Router 或 Supervisor
- **04 子 Agent 通信协议**：三种通信方式按耦合度：结构化消息（推荐）、共享状态黑板、文件/工作区引用传递；协议要素：任务契约、状态机、超时心跳、幂等、错误契约、权限收窄、版本兼容；串并行取舍：有依赖必须串行，无依赖尽量并行，并行前提是结果可合并且设并发上限
- **05 子 Agent 动态选择**：规则优先命中高频意图，模型判断兜底；Function Calling 把子 Agent 包装成工具，复用校验、超时、重试、观测；description 写能力边界、输入输出与“何时不该选”；必须有“都不选”、限次数回退、决策可观测
- **06 结论冲突处理**：不一致分四类：事实性冲突、判断性分歧、信息不对称、错误，处理方式不同；七种机制按优先级：权威数据源、依据加置信度、仲裁、辩论、投票、HITL、保守策略；预先定义裁决规则，区分“必须一致”与“允许多样”，分歧显式化并留痕
- **07 完成感知与结果回收**：感知完成四机制：同步调用、异步事件/回调、异步轮询、状态机加检查点；结果回收六要素：结构化契约、大产物走引用、摘要回传、校验后接受、部分失败语义、合并去重；用 task_id 幂等防旧结果覆盖新结果；子任务 trace 挂主 trace 保证可观测
- **08 异步消息与兜底**：消息设计：类型化、幂等键、trace 追溯、deadline、预算、错误契约、鉴权；兜底七层：退避重试、死信队列、超时取消、任务重派、降级兜底、补偿事务、告警熔断；关键认知：“消息已投递”不等于“任务已完成”，要有端到端状态确认
- **09 Markdown 传任务防漂移**：Markdown 风险：格式无约束、约束转述丢失、无 schema 无法校验、嵌套拆分误差放大；核心机制：Markdown 给人看加 JSON 给机器用双轨，机器可读部分以 JSON 为准；约束原文不可变传递、拆分后立即做覆盖/冲突/依赖/可执行校验、接收方复述确认；验收标准前置并硬性校验，限制拆分深度 2~3 层，关键节点加人工检查点
- **10 三层隔离与统一存储**：上下文隔离：独立会话/线程，只传必需最小集，大数据走引用，强隔离用独立容器；权限隔离：独立身份不共享凭证，权限降级传递，数据行级在数据层强制；存储隔离：命名空间前缀、独立凭证、工作区路径系统生成、默认私有；跨 Agent 传输优先引用加服务化取数加统一 schema 加全程鉴权，而非共享存储直读
- **11 调研类调度选型**：调研类系统几乎总选中心化，因需全局去重、冲突仲裁、预算控制、统一收敛；回退靠检查点、失败粒度化、分级重试、降级、局部重规划，语义是回退而非全量重跑；进度可观测：任务树、心跳进度、状态机、中间产物、成本预算、人工干预；设“提前收敛”：信息增益低于阈值或预算用掉 80% 即汇总
- **12 协作方式与动态分发**：除路由外还有八种协作，如 Supervisor、Pipeline、Critic、Handoff 等；Agent Team 核心：角色化、共享任务列表、自主领取、DAG 依赖管理、Owner 协调；动态分发：任务队列加状态机加原子领取，能力标签匹配，支持动态插单；分解阶段用静态，执行阶段用动态
- **13 多 Agent 效率与评估**：效率分四维：墙钟时间、质量、成本、可靠性，多 Agent 成本几乎总上升；独特价值只有上下文隔离、并行、权限合规隔离是结构性的，专业化可被同模型采样替代；评估：同模型 A/B 加四指标，成本归一化，分难度分层，失败模式分析，人工盲评；结论：装得进一个窗口的任务多 Agent 常是负收益，拆 2~5 个而不是几十个
- **14 计划外任务流转**：四问分类：是否在原目标范围内、是否有副作用/可逆、是否超授权预算、是否阻塞；流转：结构化上报→父 Agent 裁决→入队更新 DAG→子 Agent 安全暂停；范围蔓延、风险性动作、与决策冲突必须审批；范围内无副作用可自动追加；护栏：限制次数与嵌套深度、共享总预算、批量上报、默认拒绝、留痕
- **15 平台集成架构**：五层架构：接入层、平台能力层、能力供给层、治理与观测层、基础设施层；七原则：统一抽象、注册中心化、配置驱动、编排执行分离、横切收口、多租户隔离、可观测一等公民；关键取舍：“薄平台加插件化能力”，平台越厚业务越慢
- **16 核心组成与执行链路**：六大组成：模型层、规划决策层、工具能力层、记忆上下文层、编排运行时层、治理安全层；执行链路 12 步：鉴权、路由、上下文装配、Plan、Agent Loop、HITL、落库、计费；最易忽略的四环节：预算检查、工具结果处理、检查点、终止检查

### 带走三句话

1. 多 Agent 是“上下文装不下、职责隔离、任务并行”逼出来的架构选择，不是“更聪明”；单 Agent 能搞定就别拆。
2. 跨 Agent 通信一律结构化加幂等加超时心跳；消息“已投递”不等于“任务已完成”。
3. 隔离三件套：上下文独立会话加引用、权限降级传递、存储命名空间加默认私有；拆分后必校验、复述确认防漂移。
