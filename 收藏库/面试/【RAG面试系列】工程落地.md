# 【RAG面试系列】工程落地

> 一句话定位：RAG 工程落地全景：五层架构、延迟成本优化、权限隔离与生产监控。

## 摘要

本文承接 RAG 系列，讲工程落地。先给五层架构：数据层接入、解析、切分、元数据、向量化；索引层向量+关键词+元数据索引；检索层查询改写、混合检索、粗排精排、上下文压缩到 Top-5 注入；生成层分级路由；评估运维层 RAGAS、追踪、A/B 测试，并给 Qdrant/pgvector、BGE-M3 选型。再讲延迟成本优化：端到端小于 2 秒，靠缓存、量化、异步流水线、流式输出、上下文压缩、分级路由。再对比四种更新方案，提示 Embedding 升级需双索引灰度。最后讲多租户隔离与监控告警。

## 要点

- 生产级 RAG 系统分数据层、索引层、检索层、生成层、评估与运维层五层。
- 检索链路为查询改写→混合检索→粗排 Top-100→精排 Rerank→相关性过滤→上下文压缩→Top-5 注入。
- 延迟优化目标端到端小于 2 秒，典型瓶颈在 Rerank 与 LLM 生成，可用缓存、量化、异步流水线、流式输出。
- 成本优化靠 Rerank 选择性使用、上下文压缩、分级模型路由与 LLM 响应缓存，可降 30-70% 成本。
- 数据更新按文档量选择全量重建、增量索引、版本化或 Kafka 实时流式；Embedding 升级需双索引灰度切换。
- 多租户隔离有独立索引、元数据过滤、混合三种方案，权限过滤应在检索阶段 pre-filtering。
- 生产监控覆盖检索质量、生成质量、系统性能、成本、用户反馈五维，并设 Faithfulness/P95 延迟等告警。

## 提炼

> 一句话定位：RAG 工程落地全景：五层架构、延迟成本优化、权限隔离与生产监控。

### 分节提炼

- **01 架构设计与技术选型**：生产级系统分数据、索引、检索、生成、评估运维五层；检索链路：查询改写→混合检索→粗排→精排→过滤→压缩→Top-5 注入；分级模型路由：简单问题用小模型，复杂问题用大模型；选型：Qdrant/pgvector、BGE-M3、BGE-Reranker-v2-m3
- **02 延迟与成本优化**：Embedding 50-200ms、Rerank 200-500ms、LLM 500-2000ms；延迟目标端到端<2 秒，靠缓存、量化、批处理、异步流水线、流式输出；成本靠 Rerank 选择性使用、上下文压缩、分级模型与 LLM 响应缓存
- **03 数据更新策略**：全量重建简单可靠但更新不及时，增量索引实时但需变更检测；文档量<10 万全量重建，10 万-100 万增量+周校验，>100 万增量+消息队列；Embedding 升级后新旧向量不兼容，需全量重新 embedding
- **04 多租户与权限隔离**：独立索引物理隔离最强但资源浪费，元数据过滤成本低但影响召回；权限检索流程：获取权限列表→向量检索+tenant_id 过滤→细粒度 ACL 检查；元数据过滤应在检索阶段 pre-filtering，避免召回不足
- **05 监控与可观测性**：监控五维：检索质量、生成质量、系统性能、成本、用户反馈；可观测三支柱：Trace 链路追踪、Log 日志、Evaluation 定期评估；告警阈值：Faithfulness<0.85、P95>3s、错误率>1%、点踩率突增

### 带走三句话

1. 生产级 RAG 按数据、索引、检索、生成、评估运维五层落地，检索链路以 Top-5 注入收口。
2. 延迟目标端到端小于 2 秒，成本靠缓存、上下文压缩与分级模型路由可降 30-70%。
3. 权限用 tenant_id 检索时 pre-filtering，监控 Faithfulness、P95 与错误率告警。
