# 京东面试官问：你的 RAG 系统检索结果很准，但最终答案还是有幻觉，Prompt 怎么写的？System Prompt 和 User Prompt 怎么分工？

> 一句话定位：RAG 防幻觉关键在 Prompt：强约束加引用，切断参数知识与检索文档混合

## 摘要

本文拆解 RAG 的 Prompt 工程。RAG 幻觉根因是模型默认把检索文档与参数知识混合，核心任务是切断参数知识依赖。System Prompt 管规则：角色定义、“只能基于参考文档”的强约束、引用来源、数字核实、置信度标记。User Prompt 管内容：文档标编号来源、问题放文档后。措辞强弱可量化：弱约束幻觉率18%，强约束加引用降至7%。长上下文用截断、query-aware 压缩、分批处理，超32K成功率45%升到92%。最后靠版本库、忠实度与 badcase 复盘迭代。

## 要点

- 检索准≠无幻觉：幻觉来自模型把参数知识与检索文档混合使用。
- System Prompt 管规则层：定义角色、设置约束、写明负面约束。
- User Prompt 管内容层：结构化组织检索片段与问题，先文档后问题。
- 约束措辞强弱影响幻觉率，“只能/不得”比“尽量/主要”有效得多。
- 引用要求是反幻觉最显著的手段，迫使模型先找原文再写答案。
- 长上下文用截断、query-aware 压缩、分批处理，成功率45%→92%。
- 用版本库、200条测试集、忠实度指标和 badcase 复盘做系统评测。

## 提炼

> 一句话定位：RAG 防幻觉关键在 Prompt：强约束加引用，切断参数知识与检索文档混合

### 分节提炼

- **01 RAG Prompt 的独特挑战**：RAG Prompt 与普通 Prompt 根本不同：普通用参数知识，RAG 只用检索文档。；模型默认把检索文档信息与参数知识混合，这个混合就是幻觉来源。；核心任务是切断模型对参数知识的依赖，强制只从检索文档找答案。
- **02 System Prompt 设计**：System Prompt 做三件事：定义角色、设置规则、写明负面约束。；“你只能基于提供的参考文档回答”是全篇最重要的一句话，措辞强度影响行为。；五条规则：正向约束、拒绝兜底、引用来源、数字核实、置信度标记。
- **03 User Prompt 设计**：User Prompt 负责把检索片段与用户问题结构化传进去，关键是格式化。；每段文档标编号和来源，文档之间用双换行分隔。；先文档后问题的顺序比先问题后文档幻觉率更低。；结尾重申“基于文档”和“没有就说没有”，强化长上下文中被稀释的规则。
- **04 约束强弱对比**：约束措辞效果可量化：弱约束18%、中约束12%、强约束9%、强约束+引用7%。；“只能”“不得”是强制性语气，没有弹性空间，不给混入参数知识留口子。；加引用要求后，有引用的回答占比从32%升至91%。；badcase 证明：弱约束下模型会编造文档里没有的“30天等待期”。
- **05 长上下文压缩策略**：超长上下文带来超窗报错和 Lost in the Middle 两个问题。；三种策略：截断法、query-aware 压缩法、分批处理，按场景选择。；query-aware 压缩优先保留与用户问题相关的信息，而非文档自认为重要的内容。；超32K token 请求处理成功率从45%提升到92%，极端情况降级提示。
- **06 Prompt 迭代测试**：Prompt 用 Git 版本库管理，提交记录写清改动原因与测试指标变化。；核心评测指标是忠实度：回答多大比例能在检索文档里找到原文依据。；200条测试集要覆盖有答案、部分答案、无答案三类，不能只测第一类。；badcase 复盘三层深挖：检索混淆、分产品回答、引用必须含产品名。
- **07 面试回答框架**：考察五层理解：独特性、System/User分工、约束强度、长上下文、评测方法。；System 管不变的规则，User 管每次不同的内容，分工清晰、易调试、可复用。；60秒框架：强约束+引用、query-aware压缩、忠实度评测与badcase复盘。
- **08 总结**：System Prompt 是规则层，User Prompt 是内容层，各司其职。；约束用强制性语气，引用要求是反幻觉效果最显著的单一手段。；检索把对的文档找回来，Prompt 决定模型用不用这些文档。

### 带走三句话

1. RAG 幻觉根因是模型把参数知识与检索文档混合，Prompt 必须切断参数知识依赖。
2. 约束用“只能/不得”而非“尽量/主要”，并强制引用来源，幻觉率从18%降到7%。
3. 长上下文用 query-aware 压缩，Prompt 迭代靠忠实度指标与 badcase 复盘量化验证。
