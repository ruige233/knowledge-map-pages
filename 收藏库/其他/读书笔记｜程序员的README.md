# 读书笔记｜程序员的README

> 一句话定位：《程序员的README》十四章读书笔记：工程师从入门到资深的完整实践地图。

## 摘要

本文是《程序员的README》读书笔记，作者入职一年后重读该书并结合真实工作经历，按十四章梳理工程师从入门到资深的认知：新人成长与学习方法、技术债与重构、防御式编程与可观测性、依赖管理、测试、代码评审、软件交付、On-Call 运维、技术设计、可演进架构、敏捷计划、向上管理与职业规划。核心观点包括：技术债分四象限，重构宜小步渐进且克制；异常要早抛晚捕、重试需幂等；日志监控配置应规范；测试追求确定性；评审推动决断；发布后仍要负责，用特性开关与金丝雀控制风险。作者提醒技术选型保守、换工作谨慎、避免逞英雄。

## 要点

- 本书覆盖从入门、成长、编码、测试、评审、交付、On-Call 到职业规划的完整工程师认知体系。
- 新人入职应小步承接改动、用文档沉淀流程，并培养技术、执行、沟通、领导力。
- 技术债分四象限，重构宜小步渐进、务实克制，多用 IDE 与规范 commit。
- 防御式编程强调校验输入、善用异常、早抛晚捕、幂等重试与及时释放资源。
- 日志、监控、跟踪、配置都应有规范：分级、原子化、标准组件、配置即代码。
- 测试应追求确定性与可维护性：固定随机种子、注入时间戳、绑定 0 端口、清理状态。
- 代码评审要小步提交、草案先行、全面反馈并推动决断，不做橡皮图章。
- 交付靠分支策略、原子部署与特性开关、金丝雀、蓝绿等展开手段控制风险。

## 提炼

> 一句话定位：《程序员的README》十四章读书笔记：工程师从入门到资深的完整实践地图。

### 分节提炼

- **01 新手成长路径**：入门工程师晋级需具备技术知识、执行力、沟通能力、领导力四项核心能力。；新人入职建议用文档记录流程，承接小改动任务熟悉规范步骤。；坎宁安定律：想得到正确答案，先发布错误答案引发讨论。；自行车棚效应：团队易在琐碎问题上花费过多时间。
- **02 学习与提问**：学习方法多样：前置学习、实践中学习、阅读、观看讲座、结对与副业项目。；提问前先自查并设时间限制，记录背景与尝试，多用异步组播方式。；冒充者综合征用觉知、重塑、反馈三步应对；能力进阶分四阶段。
- **03 代码与技术债**：软件熵必然存在；技术债分谨慎/鲁莽、有意/无意四象限。；重构宜小步渐进，将重构提交与新特性提交分开，多用 IDE 与规范 commit。；技术选型要保守，不特立独行，不要只 fork 不 PR。
- **04 防御式编程与可观测性**：防御式编程：避免空值、保持不可变、校验输入、善用异常。；异常要早抛晚捕；重试用 backoff 指数退避，失败可 fail-fast。；日志分级、原子化、保护敏感数据；监控用标准组件并尽量测量一切。；配置即代码：版本控制、评审、校验，不玩花活、不改已部署配置。
- **05 依赖管理**：版本管理要唯一、可比、有信息性，遵循 SemVer。；相依性地狱包括循环依赖、钻石依赖、版本冲突。；规避：隔离依赖、按需显式声明、指定版本、最小化依赖范围。
- **06 测试实践**：测试既验证行为，也迫使思考接口，可作代码文档。；类型含单元、集成、系统、性能、验收测试。；确定性测试：固定随机种子、注入时间戳、绑定 0 端口、唯一路径。；避免过度测试，不依赖执行顺序，隔离并清理测试状态。
- **07 代码评审**：评审能抓 bug、教学、沉淀文档并保障安全合规。；被评审：小步改动、先出草案、勿借评审触发 CI、保持情感距离。；评审他人：分流、预留时间、理解意图、全面反馈并推动决断。
- **08 软件交付**：交付流程为构建、发布、部署、展开；分支策略分主干与特性分支。；部署要脚本化、原子化、可独立；发布保持版本不变性并频繁小步。；展开用特性开关、金丝雀、蓝绿、摸黑启动控制风险。
- **09 On-Call 运维**：On-Call 按时间表轮换，技能包含随时响应、专注、优先级、沟通、记录。；事故处理五步：分流、协同、缓解、解决、后续跟进。；把支持工作当学习机会；不要逞英雄成为单点。
- **10 技术设计**：设计是螺旋式上升过程：定义问题、技术选型、实验、留足时间。；设计文档是思考与反馈工具，需随方案迭代保持更新。；套用模板并协作设计，随时同步团队与技术负责人。
- **11 可演进架构**：复杂性来自高依赖性、高隐蔽性、高惯性。；可演进设计遵循 YAGNI、最小惊讶原则，封装领域知识。；API 保持小巧、定义良好、兼容并版本化；数据库隔离并管理 schema。
- **12 敏捷计划**：敏捷宣言重个人互动、工作软件、客户合作、响应变化。；Scrum 用冲刺、站会、评审、回顾会迭代；Kanban 用看板限制在制品。；用户故事、任务分解、故事点与积压分流是 Scrum 核心机制。
- **13 与管理者合作**：管理者负责人、产品、流程三方面；1:1、PPP、OKR 是常用沟通工具。；绩效考核要自评、环评并保留年度工作清单。；向上管理：主动索取反馈，用 SBI 框架给予反馈并讨论目标。
- **14 职业生涯规划**：职级跃迁关键：初级到资深、资深到主任/首席两次转变。；做 T 型人才，主导自己的晋升并保持工作可见。；换工作需谨慎；注意自我调节，避免过劳倦怠。

### 带走三句话

1. 把重构当最后手段：小步渐进、务实克制，过手代码要比之前更干净。
2. 永远校验输入、善用异常早抛晚捕，重试要幂等并懂得 fail-fast。
3. 发布不是结束：负责运转、及时修复，并学会与管理者合作、主导自己的晋升。
