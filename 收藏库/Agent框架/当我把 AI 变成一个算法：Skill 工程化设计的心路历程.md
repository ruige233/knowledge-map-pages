# 当我把 AI 变成一个算法：Skill 工程化设计的心路历程

> 一句话定位：把 Agent 当算法用：CLI 收走确定性事务，AI 只做理解与决策

## 摘要

本文记录作者把 Agent 改造成工程化组件的过程。核心思路是把 Agent 当算法用：保留 LLM 的理解与判断，把流程顺序、数据格式、API 调用、状态管理等确定性事务交给 CLI。规则写进 SKILL.md 超 200 行后 AI 反而叛逆，根因是注意力有限、路径不确定；引入 CLI 做执行层，用 discover 自动同步与三层分离实现热更新。Workflow 把散落工具串成流水线，靠步进披露、Gate 门禁、状态持久化、模板变量与三种步骤类型解决多步业务；最后给出无需工程化的场景判断。

## 要点

- 把 Agent 当算法用：输入自然语言、输出结构化 JSON，可预期性由执行环境保证，而非模型自觉。
- 规则写进 SKILL.md 超 200 行后 AI 反而叛逆：跳步骤、串字段、不问就执行，问题在结构不在模型。
- LLM 注意力有限，128K 上下文不等于同时注意 128K 信息，只活跃记住刚读的内容。
- 引入 CLI 做执行层：精确格式、固定流程的事交给确定性程序，Agent 只做理解、判断、表达。
- CLI 用 discover 自动同步后端工具、生成索引与 .meta/.rules，按索引/元数据/规则三层分离并热更新。
- Workflow 把散落工具串成流水线，解决流程顺序、步间通信、中断恢复三大难题。
- 五个机制支撑 Workflow：步进披露、Gate 门禁、状态持久化、模板变量、三种步骤类型。
- Workflow 是 Markdown 文件而非代码，扩展能力只增目录不改代码；单次查询等场景则不必工程化。

## 提炼

> 一句话定位：把 Agent 当算法用：CLI 收走确定性事务，AI 只做理解与决策

### 分节提炼

- **01 全文**：确定性事务全部外置给 CLI：流程顺序、数据格式、API 调用、状态管理，Agent 只留理解判断。；工具信息分索引/元数据/规则三层，Agent 上下文始终只有一张索引表，认知负担恒定。；Workflow 靠步进披露、Gate、状态持久化、模板变量与三种步骤类型，把多步业务变成流水线。；Workflow 用 Markdown 定义，新增流程只需建目录，与 Skill 同构可互转自举。

### 带走三句话

1. 确定性不能靠模型自觉，要靠结构：把流程、格式、状态外置给 CLI 这类确定性程序。
2. 多步业务别写进提示词，用文件化 Workflow 配合 Gate 与状态持久化，让 AI 只看到当前一步。
3. 扩展能力只需增删 Markdown 文件、无需改代码，系统可发现、可自举地长出新技术能力。
