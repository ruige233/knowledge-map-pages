# 用第一性原理拆解 Agentic Coding：从理论到实操

> 一句话定位：用第一性原理拆解 Agentic Coding：从 LLM 本质到工程实践

## 摘要

本文用第一性原理拆解 Agentic Coding：LLM 本质是自回归预测下一个 token，上下文即全部记忆；Attention 的平方级复杂度与注意力稀疏使有效上下文远小于标称值。强化学习让模型从「会说」进化到「会做」。Coding Agent 由消息式 API、工具调用、Prompt Caching 与 Agent Loop 构成，常见会话失忆、上下文耗尽、Dumb Zone 等问题。实操上，短对话优于长对话，精简项目配置文件，以复利工程沉淀经验，改善文档与测试等开发者体验，用工程约束驯服 Agent，并像学乐器一样刻意练习。

## 要点

- LLM 本质是自回归预测下一个 token，上下文即全部记忆，窗口之外内容对模型不存在。
- Attention 计算复杂度 O(n²) 且注意力稀疏，有效上下文远小于标称值，长上下文出现性能退化。
- RL 让模型从「会说」进化到「会做」，清晰的成功标准与允许试错能提升使用效果。
- 会话失忆、上下文耗尽、Dumb Zone 是常见问题，可用 Observation Masking 与 LLM 摘要管理。
- 短对话优于长对话：每个对话只做一件事，超过 80K-100K token 就开新对话。
- 项目配置文件是最高杠杆点，应精简（300 行以内）、渐进式披露、不替 Linter 干活。
- Compounding Engineering：把 bug 修复、代码审查等经验沉淀为可复用知识库，让系统自我改进。
- 对人难的事对 AI 也难：文档、架构、反馈循环、结构化错误的改善对人与 AI 是双倍回报。

## 提炼

> 一句话定位：用第一性原理拆解 Agentic Coding：从 LLM 本质到工程实践

### 分节提炼

- **01 局部最优≠全局规划**：逐 token 续写不等于全局规划；重构类任务会边写边想，接口不一致；测试结果需显式喂回 agent 循环
- **02 偏差滚雪球**：早期误读需求会在错误世界观里自洽；幻觉的函数名会被后续继续相信；长任务越写越像另一个项目
- **03 流式输出难回头**：擅长写新文件，不擅长最小化编辑；倾向重写而非修改，diff 过大；不变量多的仓库里尤其痛苦
- **04 约束能力有限**：边界条件、并发、错误处理易出错；跨文件符号、泛型、宏靠文本推断易漏；复杂重构需 AST/语义工具辅助
- **05 单线程难并行**：方案选择易早早押注一个方向；排查 bug 是单线推理而非并行验证
- **06 沉淀到项目文档**：AGENTS.md 是指导系统的主要途径；记录代码风格、已知陷阱、成功模式；每次对话 Agent 会读取并应用
- **07 修复产生长期价值**：修复时问能否加 lint 规则预防；把陷阱记入 Rules 或 AGENTS.md；写测试防止回归
- **08 审查提取模式**：审查意见应成为系统永久知识；判断反馈是否适用于未来类似代码
- **09 复用工作流程**：把有效模式固化为步骤清单；下次直接说按工作流程来做
- **10 优化测试**：让 Agent 运行局部测试而非全量；用 --grep 或目录限定测试范围
- **11 快速健康检查**：提供秒级验证脚本快速反馈；类型检查、变更 lint、相关测试组合
- **12 文档就近放置**：模块目录放 README 说明职责；AI 浏览目录时立即读到文档
- **13 错误信息更有用**：错误信息带错误码与解决指引；帮助 AI 与人类快速定位问题
- **14 干净实验环境**：个人项目无历史包袱，展示真实能力；专注学习与 AI 的协作
- **15 从失败学教训**：复盘 prompt 是否清晰、上下文是否足够；检查是否一个对话塞了太多任务；记录错误，避免同样陷阱
- **16 模仿高手实践**：关注公开分享 AI 工作流的开发者；差距多在用法而非工具本身
- **17 建立肌肉记忆**：何时开新对话、如何组织 prompt；工具组合直觉只能靠大量练习
- **18 投入时间**：持续有意识练习优于偶尔尝试；每天 30 分钟坚持数月效果更佳

### 带走三句话

1. 短对话、精简上下文：一个对话只做一件事，超 80K-100K token 就开新对话。
2. 把每次 bug 修复、代码审查沉淀进项目文档，让系统记住经验、持续复利。
3. 像学乐器一样刻意练习与 AI 协作，在个人项目中实验、从失败中提取教训。
