# Agent每次接新任务都像新人第一天入职？带你告别“一次性智能”

> 一句话定位：腾讯云 Forge Memory：让一次任务的工程判断真正进入下一次任务

## 摘要

本文复盘腾讯云 Forge 的 Memory 子系统：代码只说明“现在怎样工作”，难还原“为什么这样做”。工程判断跨任务要过三个断点——代码难表达理由、经验未沉淀、已存知识未被采用。Forge Memory 以连续性、准确性、安全性、复利性为目标，经四阶段形成“头部字段管路由治理、正文承载判断”的知识对象与六种角色。读取准入与沉淀准入构成知识运行时：先看知识地图再展开正文，历史判断须回到当前代码验证，沉淀默认不写入。真实任务约七成轨迹可见知识被读取并影响判断，探索路径通常缩短一半以上。

## 要点

- 代码只回答“现在怎样工作”，工程判断（选择理由、边界、取舍）随任务结束停留在上下文里，新任务需从头恢复。
- 工程判断跨任务流动有三个断点：代码难表达理由、经验未沉淀为长期知识、已存知识未被正确采用。
- Forge Memory 以连续性、准确性、安全性、复利性四目标为约束，经 Daily 日志、知识对象、双向准入、职责分层四阶段演进。
- 知识对象=头部字段（ID、范围、证据、状态等，管路由与治理）+ Markdown 正文（承载工程判断），分导航、模型、手册、诊断、理由、约束六种角色。
- 知识运行时设读取准入与沉淀准入两道门：先看知识地图再展开正文，历史判断须回当前代码验证，沉淀默认不写入。
- 职责分层：AI 做语义判断、确定性执行层做机械动作、Git 与人工审阅承担高风险团队事实。
- 真实任务中约 70% 轨迹可见知识被读取并影响判断，探索路径通常缩短一半以上；知识让探索带历史，而非跳过探索验证。

## 提炼

> 一句话定位：腾讯云 Forge Memory：让一次任务的工程判断真正进入下一次任务

### 分节提炼

- **01 三断点与四目标**：三个断点：代码难表达选择理由、经验未进入长期知识、已存知识未被找到采用。；代码回答“现在是什么”，无法还原“为什么如此、什么变化会失效”。；不能靠保存全部对话解决，需区分结果、经验与噪声。；系统要的不是保存越多越好，而是识别、投放并校正有价值经验。
- **02 建设路径四阶段**：四目标相互制约：连续性、准确性、安全性、复利性。；四阶段演进：Daily 日志、知识对象、双向准入、职责分层。；知识对象需稳定身份、适用范围、证据、状态、修正历史五属性。；系统需要读取与沉淀两道门，而不是一道。
- **03 知识对象与六种角色**：知识对象=头部字段（路由治理）+ Markdown 正文（工程判断）。；代码能回答的内容交给代码，知识只保留难从实现读出的判断。；六种角色：导航知识、模型知识、操作手册、诊断知识、决策理由、约束规则。
- **04 知识运行时两扇门**：两道门：读取准入选旧知识、沉淀准入选新经验；AI 语义判断、执行层机械动作、人审高风险。；读取先过资格门再算相关性，记忆子流程只把“知识作用”提炼回主任务。；沉淀默认不写入，五问筛出三结果：不沉淀、更新已有、新建。；冲突不轻易覆盖：补充、修正、暂不改或转人工确认。
- **05 轻量能力入口**：规则写进主 Agent 会挤占 token 与判断力，主 Agent 只需知道何时调用、结果意味着什么。；项目记忆收敛为一个入口，读取、判断、沉淀在独立上下文完成。；返回三类结果：知识作用、沉淀结果、需确认问题。
- **06 真实任务效果**：历史经验让 Agent 更早收窄排查方向、继承已有设计判断、恢复跨模块上下文。；约 70% 任务可见知识被读取并影响判断；近 30% 无需新知识、40% 以上形成更新或新对象。；知识没有让 Agent 跳过探索验证，而是让探索带历史、从已确认位置继续。
- **07 走向工程知识基础设施**：完整链路五职责：Git 来源、Knowledge 资产、Knowledge Runtime、CLI 入口、Coding Agent 消费。；五层架构：来源、知识资产、资产运行时、Access Layer、Consumer，纵向完整、横向可扩展。；愿景：成熟判断进入规则、测试、Schema、Skill 与工具，形成可积累的工程知识基础设施。

### 带走三句话

1. 代码只证明“现在如何工作”，工程判断要沉淀为带来源与边界的知识对象，才能跨任务复用并随代码演进校正。
2. 知识并非越多越好：读取与沉淀各设一道门，先过资格与相关性，再回到当前代码验证后再决定是否采纳。
3. 把记忆做成独立子流程与单一能力入口，主 Agent 只接收提炼结论，保持上下文轻量与职责清晰。
