# 蚂蚁二面被问：上下文压缩会丢失部分工具调用历史，会造成重复工具调用，怎么解决？我说清缓存，他摇了摇头

> 一句话定位：解决上下文压缩致重复工具调用：把执行状态与对话叙事拆开，辅以幂等拦截与检索。

## 摘要

Agent 跑长任务时上下文超限需压缩，而压缩有损，会在摘要生成、滑动窗口截断、注意力稀释三个环节丢失工具调用细节，导致模型重复执行同一操作。仅加缓存是打补丁，未触及漏因。正确设计是把“对话叙事”与“执行状态”拆开：独立维护不参与压缩的 Action Ledger，记录工具名、参数 hash、结果、时间戳与状态，每轮注入；执行层用函数名加参数 hash 做幂等拦截，为副作用操作兜底；必须压缩时在 prompt 中明确要求保留调用事实；长期外部化存储、按需检索，并用分层摘要降低损失。

## 要点

- 上下文压缩本质是有损处理，丢工具调用细节是必然代价而非 bug。
- 漏因有三：摘要生成阶段保大意丢细节、滑动窗口整段截断、长历史注意力稀释。
- 只加缓存是打补丁，只缓解注意力稀释的下游影响，未触及前两个漏因。
- 核心解法是把“对话叙事”与“执行状态”拆成两条线管理。
- 独立维护 Action Ledger，记录工具名、参数 hash、结果要点、时间戳、状态，不参与压缩。
- 执行层用函数名加参数 hash 做幂等拦截，为副作用操作兜底。
- 必须压缩时，摘要 prompt 要明确要求保留工具调用名称、参数与结果，避免笼统概括。
- 长期方案：调用历史外部化存储、按需检索，并用分层滚动摘要渐进压缩。

## 提炼

> 一句话定位：解决上下文压缩致重复工具调用：把执行状态与对话叙事拆开，辅以幂等拦截与检索。

### 分节提炼

- **01 为什么会漏**：压缩是有损处理，丢信息是必然代价而非 bug。；漏因分三环：摘要生成丢细节、滑动窗口截断、注意力稀释。；模型总结习惯保大意丢细节，粗线条描述替代关键参数。
- **02 状态与叙事分开**：对话历史是给人看的叙事，执行状态是给机器读的结构化数据，不能共用同一套压缩逻辑。；Action Ledger 记工具名、参数 hash、结果、时间戳、状态，独立于上下文、不参与压缩。；幂等拦截用函数名加参数 hash 生成签名，命中缓存直接返回，未命中执行并记录。
- **03 压缩提示词保细节**：必须压缩时，摘要 prompt 明确要求保留每次调用的名称、关键参数与结果要点。；模型总结很听指令，明确保留清单能大幅降低关键信息被抹掉概率。
- **04 外部化存储按需检索**：完整记录存数据库/文件/向量库，需要时主动检索而非依赖上下文窗口。；记忆容量天花板不再是上下文窗口大小，上下文只承载当前相关部分。
- **05 分层滚动摘要**：滚动摘要逐段浓缩关键动作，再逐层聚合为高层摘要。；渐进式压缩比一次性砍历史损失更小，关键事实保留概率更高。
- **06 总结**：重答思路：根源是压缩丢工具调用细节，不能只在执行层打补丁。；组合方案：独立动作清单加参数签名幂等拦截加提示词保细节加外部化检索。

### 带走三句话

1. 重复调用的根源是压缩丢了工具调用细节，光加缓存只是执行层补丁，必须回到架构上把状态与叙事拆开。
2. 用不参与压缩的 Action Ledger 记全每次调用，再以函数名加参数 hash 做幂等拦截，给副作用操作兜底。
3. 压缩不可避免时，在摘要 prompt 里明确要求保留调用事实，长期把历史外部化、按需检索并分层摘要。
