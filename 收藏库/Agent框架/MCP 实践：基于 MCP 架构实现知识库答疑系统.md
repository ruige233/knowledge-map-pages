# MCP 实践：基于 MCP 架构实现知识库答疑系统

> 一句话定位：基于 MCP 架构，用 Prompt+LLM 驱动知识库构建、检索与问答。

## 摘要

2025 年被视为 AI Agent 元年，竞争转向场景创新，MCP 已成事实标准。作者实现了一个支持私有知识库的答疑系统，分知识库构建与知识检索（RAG）两阶段：构建做文本切段、提取 FAQ 并 Embedding 导入；检索做问题拆解、向量与混合检索、内容筛选。架构分知识库、MCP Server、功能实现三层，存储用 Tablestore，Client 用 Python、Server 用 Java。文末演示建实例、启动、导入、检索、问答全流程。

## 要点

- 2025 年被业界推测为 AI Agent 元年，开源大模型能力与闭源拉齐，竞争转向应用场景创新。
- MCP 已成事实标准，OpenAI 也官宣支持。
- 系统分知识库构建与知识检索（RAG）两阶段，构建含文本切段、FAQ 提取、Embedding 导入。
- 检索含问题拆解、向量与混合检索、内容筛选，较 Naive RAG 增加 Chunk 优化、Query Rewrite 等改进。
- 架构分知识库（Knowledge/FAQ Store）、MCP Server（4 个 Tools）、功能实现三层。
- 存储选 Tablestore：简单易用、按量低成本、支持全文/向量/标量与混合检索。
- Client 用 Python、Server 用 Java + Spring AI，切段与 FAQ 提取完全由提示词完成。
- 演示给出创建实例、启动 Server、导入、检索到问答的完整流程。

## 提炼

> 一句话定位：基于 MCP 架构，用 Prompt+LLM 驱动知识库构建、检索与问答。

### 分节提炼

- **01 知识库构建**：文本切段需保证文本完整性与语义完整性；提取 FAQ 作为检索补充，以提升检索效果；文本与 FAQ 导入知识库并 Embedding 后入向量库
- **02 知识检索（RAG）**：先对输入问题拆解、重写为更原子的子问题；文本采用向量检索，FAQ 采用全文和向量混合检索；检索结果筛选后保留最相关内容用于回答
- **03 Tablestore 功能完备**：Tablestore 支持全文、向量、标量检索；同时支持混合检索
- **04 切段并提取 FAQ**：切段与 FAQ 提取完全通过提示词完成，可按需调优；切段保证完整性、语义一致性，格式处理灵活；FAQ 提取全面，简单问题直接搜 FAQ 最准最直接
- **05 写入知识库与 FAQ 库**：写入也由提示词完成；基于 MCP 架构可以非常简单地实现
- **06 问题拆解**：先对问题拆解为更原子的子问题；每个子问题分别检索知识库和 FAQ，结果汇总后筛选
- **07 按格式返回结果**：检索结果按指定格式返回；保证输出结构统一，便于后续问答
- **08 创建存储实例**：通过命令行工具创建 Tablestore 实例；实例名自行选择，需保证 Region 内唯一
- **09 启动 MCP Server**：启动前需在环境变量内配置参数；可参考 README 启动，或 IDE 直接运行 App 类；启动后自动初始化表和索引
- **10 导入知识库**：执行 knowledge_manager.py 工具导入；执行前需配置访问大模型的 API-KEY，默认 qwen-max；知识库文档使用 markdown 格式
- **11 检索知识库**：执行对应命令即可完成知识库检索；在已导入的知识库上运行检索
- **12 基于知识库问答**：执行命令基于知识库进行问答；MCP Server Log 显示自动调用知识库和 FAQ 检索工具；根据之前导入的内容进行回答

### 带走三句话

1. MCP 已成事实标准：用 Prompt+LLM 即可编排知识库导入、检索与问答，无需编写业务代码。
2. 叠加 Chunk 优化、FAQ 提取、Query Rewrite 与混合检索，让私有知识库问答更准。
3. 切段与 FAQ 提取交给大模型虽准但慢且耗 Token，是一次性投入，适合离线批量构建。
