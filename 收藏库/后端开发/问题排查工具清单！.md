# 问题排查工具清单！

> 一句话定位：Java 问题排查工具速查：Linux 命令、JDK 工具与 IDEA 插件

## 摘要

本文是一份问题排查工具速查清单，分 Linux 命令、JDK 自带工具、IDEA 插件三块。Linux 部分给出 tail -f、grep、awk、find、top、netstat 等命令及参数；JDK 工具介绍 jps、jstack、jinfo、jmap、jstat、jdb 的典型用法，如 jmap 看堆、dump、histo，jstack 抓线程栈，jstat -gcutil 看 GC。另给出 VM 参数：-XX:+TraceClassLoading 定位类加载来源，-XX:+HeapDumpOnOutOfMemoryError 在 OOM 时导出堆。IDEA 插件推荐 key promoter、maven helper、Alibaba Java Coding Guidelines、GrepConsole 等。jar 包冲突可用 mvn dependency:tree 排查；进程莫名消失用 dmesg 查 OOM killer。

## 要点

- tail -f / tail -300f 实时监听日志文件写入，是最常用的排查命令
- grep 支持多文件、递归目录、前后文 -A/-B/-C 及 --exclude 反匹配
- awk 用 NR/FNR/NF 内建变量与 -F 分隔符做列处理与匹配
- find 可按名称、类型、大小、权限、时间（-atime/-mtime/-amin 等）定位文件
- JDK 工具链：jps -mlvV 看进程、jstack 抓栈、jmap 查堆、jstat -gcutil 看 GC
- VM 参数 -XX:+TraceClassLoading 定位类来源，-XX:+HeapDumpOnOutOfMemoryError 挂时留堆
- jar 包冲突用 mvn dependency:tree（-Dverbose -Dincludes）定位依赖关系
- 进程被系统 OOM Killer 杀死时，用 dmesg | grep -i kill 找 oom_killer 线索

## 提炼

> 一句话定位：Java 问题排查工具速查：Linux 命令、JDK 工具与 IDEA 插件

### 分节提炼

- **01 awk 基础命令**：awk '{print $4,$6}' 打印指定列，NR/FNR/FILENAME/NF 内建变量可辅助输出；echo 1:2:3:4 | awk -F: '{print $1,$2,$3,$4}' 用 -F 指定分隔符
- **02 awk 匹配**：awk '/ldb/ {print}' 按正则匹配行，!/ldb/ 反向匹配；awk '/ldb/ && /LISTEN/ {print}' 可组合多个匹配条件；$5 ~ /ldb/ 只对第 5 列做匹配
- **03 awk 内建变量**：NR 是 awk 开始执行后累计读取的记录数，默认等于行数；FNR 每处理一个新文件从 1 重新计数，适合多文件场景；NF 是当前记录被分割出的字段数目
- **04 查看堆情况**：jmap -heap 2815 查看进程堆的总体情况
- **05 导出堆 dump**：jmap -dump:live,format=b,file=/tmp/heap2.bin 2815 导出存活对象堆；去掉 live 则用 jmap -dump:format=b,file=/tmp/heap3.bin 2815 导出全量堆
- **06 堆占用 Top 类**：jmap -histo 2815 | head -10 快速看堆被哪些类占用 Top10
- **07 追踪类加载来源**：加 -XX:+TraceClassLoading 可打印每个类从哪个文件加载；输出形如 [Loaded java.lang... from rt.jar]，直接定位来源
- **08 OOM 自动留堆**：-XX:+HeapDumpOnOutOfMemoryError 让应用 OOM 时自动生成堆 dump；-XX:HeapDumpPath=/home/admin/logs/java.hprof 指定 dump 输出路径

### 带走三句话

1. 排查先看日志：tail -300f 实时监听，grep 递归加 -C 看上下文。
2. 进程/内存问题认准 JDK 工具链：jps、jstack、jmap、jstat 各管一段。
3. 兜底两招：jar 冲突用 mvn dependency:tree，进程消失查 dmesg 的 oom_killer。
