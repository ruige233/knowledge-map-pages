# 一文带你弄懂 MySQL 的加锁规则！

> 一句话定位：以丁奇“两原则、两优化、一bug”拆解 MySQL Innodb 加锁规则

## 摘要

本文讲解 MySQL Innodb 加锁规则。全局上，Server 层与存储引擎逐条记录循环交互，row_search_mvcc 每轮加锁，范围查询首次定位属精确查找。核心是丁奇总结：两个原则——基本单位是前开后闭的 Next-Key 锁、访问到的对象才加锁；两个优化——等值且唯一索引退化为行锁、等值向右最后值不满足时退化为间隙锁；一个 bug——唯一索引范围查询会访问到第一个不满足条件的值。再用建表 t 四个例子验证锁区间，指出覆盖索引不回表则聚簇索引不加锁。实际特例仍多，需继续积累。

## 要点

- Server 层与 Innodb 是逐条记录循环交互，并非一次性取数。
- row_search_mvcc 在每次循环中执行具体的加锁逻辑。
- 范围查询首次定位是精确查找，找到后才转为范围查找。
- 加锁总纲：两个原则、两个优化、一个 bug。
- 默认加 Next-Key 锁（前开后闭），再按优化退化为行锁或间隙锁。
- 索引覆盖不回表时，聚簇索引不加锁。
- 唯一索引范围查询会访问到不满足条件的第一个值（bug）。
- limit、非唯一索引多值等特例会影响锁范围，需继续积累。

## 提炼

> 一句话定位：以丁奇“两原则、两优化、一bug”拆解 MySQL Innodb 加锁规则

### 分节提炼

- **01 选资料定学习路径**：以《MySQL 45 讲》丁奇总结与源码文章作为两大资料。；加锁规则无明显简单规律，需用动态眼光看待。；学习路径：先按丁奇规则学，再深入源码补细节。
- **02 两层循环交互**：Server 层与 Innodb 逐条记录循环交互，并非一次取数。；row_search_mvcc 负责具体加锁，循环中执行多次。；范围查询首次定位是精确查找，随后才转范围查找。
- **03 两原则两优化一bug**：总纲：两个原则、两个优化、一个 bug。；默认先加 Next-Key 锁，再按优化选择性退化。；索引覆盖不回表则聚簇索引不加锁。
- **04 等值间隙锁示例**：查 id=7：先加 Next-Key (5,10]，优化 2 退化为间隙锁 (5,10)。；插入 id=8 被阻塞，修改 id=10 这一行可行。
- **05 非唯一索引等值示例**：查 c=5：在索引 c 上加 (0,5] 与 (5,10)。；覆盖索引不回表，主键索引不加锁。；插入 c=7 落入 (5,10) 间隙被阻塞。
- **06 主键范围锁示例**：id=10 与 id>=10 and id<11 逻辑等价但加锁不同。；先加 (5,10]，等值 id=10 退化为行锁。；继续范围查找，对 id=15 加 Next-Key (10,15]。
- **07 非唯一索引范围示例**：非唯一索引范围查询不退化，加 (5,10] 与 (10,15]。；操作 c=8 与 c=15 的数据会被阻塞。
- **08 总结**：先懂两层多次交互，再按两原则分析锁范围。；再按两优化退化，核心是唯一索引与等值查询。；limit、非唯一索引多值等特例仍需继续积累。

### 带走三句话

1. Innodb 默认加 Next-Key 锁，先按两个原则分析，再按两个优化退化。
2. 覆盖索引不回表时聚簇索引不加锁，能减少阻塞。
3. 范围查询首次定位是精确查找，找到目标后才转入范围查找。
