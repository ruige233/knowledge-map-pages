# 两万字！多线程硬核50问！

> 一句话定位：Java 多线程核心面试 50 问速查

## 摘要

本文系统盘点 Java 多线程高频面试 50 问，从为什么用多线程、创建线程方式、start 与 run 区别、线程与进程区别等基础概念切入，逐步展开 volatile 可见性与内存屏障、synchronized 实现原理与锁优化、线程状态、CAS 缺陷、伪共享、Fork/Join、ThreadLocal 原理与内存泄漏、AQS 与 Semaphore、线程池核心参数与调优、死锁检测与 happens-before 原则等内容，并结合代码示例给出最佳实践。

## 要点

- 多线程在正确场景与恰当线程数下可提高 CPU/IO 利用率，但加锁不当会耗性能。
- Java 创建线程有继承 Thread、实现 Runnable/Callable、线程池四种方式。
- volatile 通过内存屏障保证可见性、禁止重排，但不保证原子性。
- synchronized 经偏向锁、轻量级锁、自旋、锁消除/粗化优化后性能已不弱于 ReentrantLock。
- ThreadLocal 以弱引用 key 实现线程隔离，线程池场景需及时 remove 避免内存泄漏。
- AQS 用 volatile state、CLH 队列与模板方法支撑 ReentrantLock/Semaphore 等同步器。
- 线程池核心参数决定任务执行流程，禁止用 Executors 快捷方法创建，需按场景调优线程数。

## 提炼

> 一句话定位：Java 多线程核心面试 50 问速查

### 分节提炼

- **01 为什么用多线程**：多线程为提升程序运行速率，充分利用CPU和I/O利用率；需选恰当线程数，并注意加锁不当会耗性能
- **02 创建线程方式**：创建线程有继承Thread、实现Runnable、实现Callable、线程池四种；Callable配合Future/FutureTask可获取返回值；日常开发一般用线程池执行异步任务
- **03 start与run区别**：start启动新线程、实现多线程，run只是普通方法；start不可重复调用，run可多次调用；直接调用run需等代码执行完，start可线程切换
- **04 线程与进程区别**：进程是资源分配最小单位，线程是CPU调度最小单位；一个进程可有多个线程，线程共享进程资源；线程无独立地址空间，切换代价小于进程
- **05 Runnable与Callable**：Runnable的run无返回值且不能上抛异常；Callable的call有泛型返回值、可抛异常；Callable一般配合Future、FutureTask获取异步结果
- **06 volatile原理**：volatile保证可见性、禁止重排，但不保证原子性；JMM中变量存主内存，线程在工作内存操作副本；lock前缀指令即内存屏障，写回缓存并使其他缓存失效
- **07 并发与并行**：顺序/串行是一个接一个执行，并发可交替执行；并行是物理上多执行单元同时执行；关键区别在于是否同时
- **08 synchronized原理**：代码块用monitorenter/monitorexit实现，方法用ACC_SYNCHRONIZED标记；HotSpot中Monitor由ObjectMonitor实现，含_EntryList/_WaitSet；重量级锁时Mark Word锁标识位为10，指向Monitor起始地址
- **09 线程状态**：线程有New/Runnable/Blocked/Waiting/Timed_Waiting/Terminated六态；Runnable含ready与running两态；wait进入Waiting，sleep进入Timed_Waiting，锁阻塞进入Blocked
- **10 synchronized与ReentrantLock**：synchronized由JVM实现，ReentrantLock是API实现；synchronized经锁优化后性能与ReentrantLock相当；ReentrantLock可指定公平锁、可响应中断
- **11 wait与suspend**：wait阻塞并释放锁，notify唤醒等待线程；suspend阻塞后不释放资源、需resume恢复；suspend易死锁，不建议使用
- **12 CAS缺陷**：CAS比较并交换，V与A相等则更新为B；ABA问题可用AtomicStampedReference版本号解决；CAS只能保证单变量原子操作，多变量可用锁或AtomicReference
- **13 CountDownLatch与CyclicBarrier**：CountDownLatch是等其余线程完成后再执行；CyclicBarrier是多个线程互相等待到同一同步点一起执行
- **14 伪共享**：缓存行64字节，独立变量同处一行时互相失效影响性能；数据填充把独立变量分散到不同缓存行，以空间换时间
- **15 Fork/Join框架**：Fork/Join是Java7并行框架，大任务拆分汇总；工作窃取用双端队列让快线程抢慢线程任务，减少锁竞争
- **16 ThreadLocal原理**：每个Thread有ThreadLocalMap，Entry的key是ThreadLocal本身；set/get以当前线程取map，实现线程隔离
- **17 ThreadLocal内存泄漏**：key为null的Entry的value无法访问且线程不死导致泄漏；get/set/remove会自动清理key为null的Entry；线程池复用线程时需手动remove防OOM
- **18 key为何弱引用**：key强引用时ThreadLocal被回收后仍泄漏；key弱引用使ThreadLocal可被回收，value下次get/set/remove被清除；根本原因是不再使用的Entry未从ThreadLocalMap删除
- **19 父子线程共享数据**：InheritableThreadLocal可让子线程继承父线程值；Thread.init将父线程inheritableThreadLocals拷贝给子线程
- **20 i++原子操作**：可用循环CAS、锁机制或synchronized实现原子自增；AtomicInteger.incrementAndGet基于CAS
- **21 死锁条件与预防**：死锁四条件：互斥、占有且等待、非抢占、循环等待；预防：加锁顺序、加锁时限、死锁检测
- **22 线程过多的影响**：过多线程增加启动销毁与共享资源开销；应使用线程池并设置恰当线程数
- **23 happens-before**：八大规则包括程序次序、管程锁定、volatile、线程启动终止等；传递性：A先于B且B先于C则A先于C
- **24 线程间共享数据**：可用类变量、并发数据结构、volatile或锁、atomic类
- **25 LockSupport**：park挂起线程，unpark恢复线程；park/unpark每个线程维持一个许可证，unpark可先于park调用
- **26 最佳线程数**：最佳线程数=（等待时间+CPU时间）/CPU时间×CPU数目；8核、20ms CPU+80ms等待时最佳为40
- **27 为什么用线程池**：管理线程、降低创建销毁损耗、提高响应速度、复用线程
- **28 线程池执行原理**：核心线程比正式员工、阻塞队列比需求池；提交任务先核心线程，再队列，再非核心线程
- **29 线程池核心参数**：核心参数：corePoolSize、maximumPoolSize、keepAliveTime、unit、workQueue、threadFactory、handler；四种拒绝策略：AbortPolicy、DiscardPolicy、DiscardOldestPolicy、CallerRunsPolicy；工作队列有ArrayBlockingQueue、LinkedBlockingQueue、DelayQueue、PriorityBlockingQueue、SynchronousQueue
- **30 任务异常处理**：submit提交任务异常无输出，需try/catch捕获；也可通过Future.get重新抛出异常
- **31 AQS原理**：AQS用volatile int state表示同步状态；CLH队列是FIFO双向队列，获取失败线程入队阻塞；独占如ReentrantLock，共享如Semaphore/CountDownLatch
- **32 Semaphore原理**：Semaphore控制同时访问资源的线程数；构造时把令牌数赋给AQS的state；acquire用CAS扣减，release唤醒共享节点线程
- **33 synchronized锁优化**：JDK6起引入适应性自旋、锁消除、锁粗化、轻量级锁、偏向锁；偏向锁无竞争时只存线程指针，轻量级锁减少互斥量开销；自旋锁减少CPU上下文切换，锁粗化合并连续加解锁
- **34 上下文切换**：CPU上下文指寄存器和程序计数器；切换即保存旧任务上下文并加载新任务上下文；线程时间片用完让出CPU即线程上下文切换
- **35 wait为何在Object**：锁是对象头里的标记，wait/notify操作对象锁；面向对象角度：开锁关锁方法属于门对象而非人；观察者角度：被观察者对象轮询通知观察者线程
- **36 submit与execute**：execute只能提交Runnable，submit还能提交Callable；execute直接抛异常，submit吞异常需Future.get重抛
- **37 AtomicInteger原理**：AtomicInteger底层基于Unsafe的CAS实现；getAndAddInt循环compareAndSwapInt直至成功
- **38 线程调度算法**：分时调度轮流平均分配时间片，抢占式按优先级抢占；Java默认采用抢占式调度
- **39 shutdown区别**：shutdown关闭提交通道，已提交任务跑完再停；shutdownNow立即停止运行与等待任务，风险大
- **40 常见线程池**：newFixedThreadPool固定线程数，适合CPU密集长期任务；newCachedThreadPool核心为0、最大Integer.MAX_VALUE，空闲60秒回收；newSingleThreadExecutor串行执行，newScheduledThreadPool周期执行
- **41 FutureTask**：FutureTask是可取消的异步计算，实现Runnable和Future；可获取返回结果、提供超时控制；底层基于生产者消费者模式
- **42 interrupt三方法**：interrupt真正触发中断；interrupted是类方法且清除中断标志位；isInterrupted是实例方法，判断是否被中断
- **43 线程顺序执行**：用join让主线程等待前一线程执行完再启动下一线程
- **44 阻塞队列盘点**：常见有ArrayBlockingQueue、LinkedBlockingQueue、PriorityBlockingQueue；还有DelayQueue、SynchronousQueue、LinkedTransferQueue、LinkedBlockingDeque
- **45 ConcurrentHashMap并发度**：并发度即segment个数，通常是2的N次方，默认16
- **46 线程调度方法**：sleep进入Timed_Waiting后自动转Runnable；interrupt的InterruptedException由线程在wait/sleep/join中抛出；wait等待notify/notifyAll唤醒，yield让出执行机会
- **47 ReentrantLock原理**：ReentrantLock支持同线程重复获取锁；无参构造默认非公平锁，可传fair指定公平/非公平；公平锁按序排队不易饿死但吞吐低，非公平锁吞吐高但可能饿死
- **48 线程通讯方式**：volatile/synchronized保证可见与排他；wait/notify实现等待通知机制；管道流用于线程间内存数据传输，join等待线程终止，ThreadLocal线程隔离
- **49 多线程最佳实践**：多用同步类少用wait/notify，少用锁并缩小同步范围；给线程命名、多用并发集合少用同步集合
- **50 禁Executors建池**：Executors快捷创建的线程池实现类有坑；newFixedThreadPool和newCachedThreadPool有内存泄漏隐患

### 带走三句话

1. 先弄清 volatile、synchronized、CAS 的可见性/原子性边界，再谈锁优化。
2. 线程池要手写核心参数并设置合理线程数，禁止 Executors 快捷创建。
3. ThreadLocal 用后及时 remove，线程池长生命周期下更易内存泄漏。
