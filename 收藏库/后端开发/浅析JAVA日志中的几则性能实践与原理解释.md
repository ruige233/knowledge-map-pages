# 浅析JAVA日志中的几则性能实践与原理解释

> 一句话定位：从压缩内容、解耦通道、按需执行三方面提炼Java日志性能实践

## 摘要

文章以物流运输类比日志链路，提出冰山法则下的三层优化思路：避免通道拥塞、减少看得见的业务开销、躲开看不见的系统开销。在通道层，通过压缩Logger名称、精简异常堆栈、异步日志与滚动日志来减少输出内容并解耦依赖；在业务层，先用isXXEnabled判定再执行重操作，用占位符延迟拼接，并给出短字符拼接更快、长字符占位符更快的测试结论；在系统层，介绍log4j2的Garbage Free减少GC压力，以及避免行号等元信息打印以省去Location计算开销。全文实践源自EDAS团队工单答疑。

## 要点

- 日志性能遵循冰山法则，优化分三层：避免通道拥塞、减少可见业务开销、躲开不可见系统开销。
- 更大的日志内容只会导致更差的处理时间，写内存与写磁盘的吞吐都随内容增大而下降。
- 用%logger{5}压缩Logger的FQCN输出，平均每条日志减少19字符，但会额外消耗CPU。
- 异常堆栈只保留栈顶几帧与业务栈帧，抽样打印全栈，兼顾性能与可追溯。
- 异步日志解耦业务与通道，AsyncLogger基于Disruptor队列，吞吐优于AsyncAppender。
- 用isXXEnabled()先判级再执行重操作，占位符延迟拼接，短字符拼接更快、长字符占位符更快。
- log4j2的Garbage Free复用对象避免GC，但J2EE热加载场景可能内存泄漏，默认禁用。
- 行号等元信息打印需构建Throwable获取Location，几乎所用框架性能都会急剧下降。

## 提炼

> 一句话定位：从压缩内容、解耦通道、按需执行三方面提炼Java日志性能实践

### 分节提炼

- **01 日志通道与冰山法则**：日志写入磁盘像物流运输，日志框架(log4j/logback/jul)封装技术细节，程序员只需使用Logger。；性能遵循冰山法则，优化思路：避免通道拥塞、减少可见业务开销、躲开不可见系统开销。
- **02 压缩内容与解耦通道**：更大的日志内容只会导致更差处理时间，写内存与写磁盘吞吐均随内容增大而下降。；压缩Logger输出：%logger{5}把FQCN压成c.a.e.d.PoweredByEdas，每条省19字符。；压缩异常输出：只保留栈顶几帧和业务栈帧，抽样打印全栈。；异步日志解耦业务与通道，AsyncLogger用Disruptor队列性能更优；滚动日志切小文件便于运维。
- **03 按需执行与延迟拼接**：用logger.isXXEnabled()先判定级别，再执行查询数据库、JSON序列化等昂贵操作。；占位符延迟拼接更易读且省开销；短字符拼接更快，长字符占位符反超（log4j2复用StringBuilder）。
- **04 Garbage Free与元信息**：Garbage Free通过ThreadLocal与复用ByteBuffer减少GC压力，显著降低延迟。；避免行号等元信息打印；Log4j2获取Location需构建Throwable反查栈帧，开销大。
- **05 Java日志性能实践总结**：实践源自EDAS团队日志配置相关工单答疑，覆盖内容、通道、系统开销三个层面。；作者提示经验有限，欢迎补充；EDAS提供运行时动态调整日志配置的能力。

### 带走三句话

1. 日志优化先分清能控与不能控：能控的尽量优化，不能控的尽量解耦。
2. 少打、短打、按需打：压缩名称与堆栈，先判级再执行，用占位符延迟拼接。
3. 异步优先选AsyncLogger，生产上慎用行号等元信息并留意Garbage Free的内存泄漏风险。
