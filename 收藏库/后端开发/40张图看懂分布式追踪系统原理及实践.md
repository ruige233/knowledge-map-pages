# 40张图看懂分布式追踪系统原理及实践

> 一句话定位：40张图详解分布式追踪原理与SkyWalking架构落地

## 摘要

本文讲分布式追踪原理与SkyWalking实践。单体架构用 AOP 算 RT 与异常；微服务无法定位请求路径，带来排查难、难复现、瓶颈分析难。OpenTracing 以 Trace、Span、SpanContext 建模，Collector 采全局与父子标识还原链路。SkyWalking 靠插件化无侵入采集，attachment 传 context，snowflake 生成 traceId，3 秒采样 3 次控开销。我司只取 agent 采样，自研强制采样、分组采样、日志嵌 traceId。

## 要点

- 单体架构用 AOP 在业务逻辑前后打印时间并 catch 异常，即可算出 RT、异常与慢点。
- 微服务下无法准确定位请求路径，带来排查难、难复现、性能瓶颈分析难三大痛点。
- OpenTracing 用 Trace、Span、SpanContext 建模，Collector 采集 trace_id、span_id、parent_span_id 还原调用链。
- SkyWalking 靠 javaagent+插件化无侵入采集 span，在 header/attachment 中传递 context。
- traceId 用 snowflake 本地生成避免发号器开销，时间回拨时退化为随机数并避免过度设计。
- 默认 3 秒采样 3 次，上游携带 Context 时下游强制采集以保链路完整。
- 官方测评 TPS 5000 下 SkyWalking 性能损耗可忽略，响应时间 22ms 优于 Zipkin 117ms、Pinpoint 201ms。
- 我司只取 agent 采样，自研强制采样、分组采样、日志嵌入 traceId 与 memcached/druid 插件。

### 分节提炼

- **01 全文**：追踪链路核心是 trace_id、span_id、parent_span_id，三者即可还原完整调用链。；SkyWalking 由采样、上报分析、存储、可视化组成；我司只取 agent 采样，避免替换成本。；插件三要素：插件定义类、Instrumentation 指定切面切点、Interceptor 写前后置增强逻辑。；引入技术要结合现有架构取舍，没有最好技术只有最合适技术，避免过度设计。

### 带走三句话

1. 给每次调用挂全局 traceId，用 trace_id、span_id、parent_span_id 还原链路定位慢点。
2. SkyWalking 靠插件化无侵入采集、采样与本地 snowflake 生成 ID 控开销，性能损耗可忽略。
3. 落地按需取舍组件：我司只复用 agent 采样并自研插件，没有最好技术只有最合适技术。
