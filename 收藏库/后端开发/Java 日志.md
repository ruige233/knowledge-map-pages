# Java 日志

> 一句话定位：Java 日志三层抽象：接口层、实现层、适配层，及绑定与桥接两种适配能力。

## 摘要

本文用一篇短文厘清 Java 日志体系的三层抽象。日志发展到今天被抽象成三层：接口层、实现层和适配层。接口层也叫日志门面（facade），本质是只定义接口、等待别人实现的 interface。实现层是真正干活、能把日志记录下来的工具，但它并不是接口层的实现——它不感知也不直接实现接口，而是独立实现。适配层一般称为 Adapter，才是接口层真正的 implements；因为接口层与实现层常出自不同厂商、无法直接匹配，便引用“任何计算机问题都可以通过增加一个中间层来解决”的思路，由适配层来对接。适配层进一步分为两种能力：绑定（Binding）把接口层绑定到某个实现层；桥接（Bridging）把接口层桥接到另一个接口层，方便用户在各接口层与适配层之间低成本迁移。

## 要点

- 日志体系被抽象为接口层、实现层、适配层三层。
- 接口层即日志门面（facade），只定义 interface，不负责实现。
- 实现层真正记录日志，但不感知、也不直接实现接口层。
- 适配层（Adapter）才是接口层的 implements，用于解决两方不匹配。
- 适配层分为绑定（Binding）与桥接（Bridging）两种能力。
- 绑定把接口层连到实现层，桥接把接口层连到另一个接口层。
- 增加中间层（indirection）是计算机科学的通用解法。

3. Java 日志体系的思路就是增加中间层，解决接口与实现之间的不匹配。
