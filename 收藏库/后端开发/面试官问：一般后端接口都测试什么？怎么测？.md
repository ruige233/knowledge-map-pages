# 面试官问：一般后端接口都测试什么？怎么测？

> 一句话定位：梳理后端接口测试内容、做法及其与前端测试的异同

## 摘要

文章回答两个高频问题：后端接口测什么、怎么测，以及接口测试与前端测试是否重复。接口测试主要覆盖基本功能、边界分析、性能测试，基于 http 协议用工具或代码模拟请求收发。与 App 端测试相比，两者在功能、边界、性能上有重叠：功能测试重合度最高；边界分析中接口覆盖更广、更易出错；性能测试中 App 关注手机 cpu、内存、流量、fps，接口关注响应时间、并发与服务端资源，需分开测试。接口测试易自动化持续集成、支持快速发版，并在前后端分离下从接口层验证安全与加密。

## 要点

- 接口测试主要覆盖基本功能、边界分析、性能测试，并通过工具模拟 http 请求收发。
- 接口测试与 App 测试在功能、边界、性能上有重叠，但各自关注点不同，需分开测试。
- 边界分析中，前端常受固定输入限制，接口覆盖范围更广、出问题概率更高。
- 性能测试上，App 关注手机 cpu/内存/流量/fps，接口关注响应时间、并发与服务端资源。
- 接口测试易自动化持续集成，可减少人工回归成本、缩短周期、支持快速发版。
- 前后端分离下不能只依赖前端限制，需在接口层验证后端控制与敏感信息加密。
- 接口自动化已用于回归阶段，后续向全流程、结果展示、定位、校验、覆盖率和性能扩展。
- 质量评估标准涵盖业务功能/规则、参数验证、异常场景、接口与代码覆盖率、性能与安全指标。

## 提炼

> 一句话定位：梳理后端接口测试内容、做法及其与前端测试的异同

### 分节提炼

- **01 接口测试测什么怎么测**：接口测试活动内容包括基本功能、边界分析、性能测试等；基于 http 协议的接口通过工具或代码模拟请求收发，如 postman、jmeter、soupUI、java+httpclient
- **02 接口与前端测试是否重复**：接口测试与 App 端测试相同的部分是功能、边界分析和性能测试；其它部分因各自特性或关注点不同，需单独进行特殊测试
- **03 基本功能测试**：针对基本业务功能进行测试，是两种测试重合度最高的一块；开发同学通常所指的也主要是这部分内容
- **04 边界分析测试**：在基本功能测试基础上考虑输入输出边界条件，也有重复部分（如业务规则边界）；前端输入输出常提供固定值让用户选择，边界范围有限；接口覆盖范围更广、出问题概率更高
- **05 性能测试**：都需要做性能测试，但关注点大不相同；App 端关注手机 cpu、内存、流量、fps；接口关注响应时间、并发、服务端资源使用；两种测试策略和方法区别大，需分开单独进行；接口测试关注服务器逻辑验证，UI 测试关注页面展示逻辑及前端与服务器集成验证
- **06 接口测试定义**：接口测试是测试系统组件间接口的一种测试；重点检查数据交换、传递和控制管理过程，以及系统间逻辑依赖关系
- **07 接口测试的价值**：系统复杂度上升，传统测试方法成本高、效率下降；接口测试易自动化持续集成且较 UI 自动化稳定，可减少人工回归成本、缩短周期、支持快速发版；前后端分离下只依赖前端限制不够，需从接口层验证后端控制，并验证传输与日志是否加密（身份证、银行卡等隐私）
- **08 持续集成自动化**：持续集成自动化是接口测试核心，目前主要应用于回归阶段；后续加强方向：流程全自动化、结果展示、问题定位、结果校验、代码覆盖率、性能监控
- **09 质量评估标准**：从业务功能覆盖、业务规则覆盖、参数验证、异常场景覆盖、接口覆盖率、代码覆盖率、性能指标、安全指标八方面评估

### 带走三句话

1. 接口测试与前端测试在功能、边界、性能上有重叠，但关注点不同，需分开做针对性测试。
2. 接口测试核心靠自动化持续集成实现低成本高收益，已在回归阶段落地并逐步全流程化。
3. 前后端分离下安全不能只靠前端，接口层要验证后端控制与敏感信息加密。
