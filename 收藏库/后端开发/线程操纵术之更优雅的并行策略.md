# 线程操纵术之更优雅的并行策略

> 一句话定位：从家务奥数题讲透Fork/Join与并行流，真实案例前置长调用提速近3倍

## 摘要

本文从家务奥数题切入，引出并行调度贪婪思想：空闲时永远先做耗时最大的任务，小任务留到最后。随后讲 Java 并行编程：并发与并行之别、Fork/Join 分而治之与工作窃取、parallelStream 默认用 commonPool() 的注意点。真实案例耗时从流并行 4.85s、ForkJoinTask 3.3s 到前置长调用 fork 1.65s，核心是先 fork 大任务。最后总结并行最佳实践与 parallelStream deadlock 风险，建议自建 ForkJoinPool。

## 要点

- 并发是多个任务交替执行，并行是多个任务同时执行，后者需要多处理器或资源支持。
- Fork/Join 框架靠分而治之与工作窃取提升并行度，但划分与合并规则、拆分阈值需自行指定。
- 工作窃取：线程以 LIFO 访问自己的队列，以 FIFO 窃取他人队列末尾的大任务，并随机选队以减少争用。
- parallelStream() 默认使用共享的 ForkJoinPool.commonPool()，存在线程池资源竞争与并发风险。
- 真实业务优化：未优化 4.85s→ForkJoin 改造 3.3s→前置长调用 fork 1.65s，核心是先 fork 大任务。
- 并行流最佳实践：确定规模、选合适数据结构、注意竞态条件、避免有状态操作、按场景调整并行度。
- 所有 parallelStream 共用一套 commonPool，线程池内部阻塞、static 块迭代、迭代中改 list 都可能 deadlock。
- 用全链路 Trace 观测调用，可直观发现长调用未并行、中短调用抢占 CPU 等调度问题。

## 提炼

> 一句话定位：从家务奥数题讲透Fork/Join与并行流，真实案例前置长调用提速近3倍

### 分节提炼

- **01 并行编程基础**：并发是交替执行、并行是同时执行；并行需要多处理器或资源支持。；Fork/Join 不自行分割与合并任务，需自定划分方法、合并方法与拆分阈值。；只提交根任务 invoke()，子任务无需提交，RecursiveTask 自分裂。；工作窃取：自己队列 LIFO 取小任务，窃取他人队列 FIFO 取大任务，随机选队。
- **02 真实业务优化案例**：问题抽象为树遍历找特定节点：先长调用，再执行依赖其结果的中短调用。；初始 parallelStream 写法体感无并行，Trace 显示长调用未能理想并行。；自定义 ForkJoinTask 后长调用可并行，但中短调用先占满 CPU，大任务未前置。；前置长调用 fork 后长调用永远最先并行，总耗时由 4.85s 降到 1.65s。
- **03 总结与风险**：更优雅的并行程序：吃透业务逻辑、贪婪策略调度线程、遵循最佳实践。；并行不是银弹，需确定规模、合适数据结构、避免有状态操作并分场景调并行度。；所有 parallelStream 共用一套 commonPool，deadlock 全局阻塞。；建议创建独立 ForkJoinPool 替代默认公共线程池，以控制并行执行环境。

### 带走三句话

1. 空闲时先做/先 fork 耗时最大的任务，把更多小任务留到最后，是并行调度的核心贪心思想。
2. 并行流默认共享 commonPool，有资源竞争与 deadlock 风险，关键场景应自建 ForkJoinPool。
3. 并行不是银弹：确定规模、选对数据结构、避免有状态操作，并前置大任务才能发挥并行价值。
