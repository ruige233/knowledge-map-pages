# 你管这破玩意叫文件系统

> 一句话定位：从零推导一个类 ext2 的极简文件系统

## 摘要

文章从一块 1MB 硬盘出发，一步步推导文件系统设计：先把硬盘划分为 1KB 的块，用块位图记录块的使用情况；为按名访问文件，引入 128 字节的 inode 存元信息并指向数据块，再用 inode 位图管理 inode、inode 表存放 inode。对大文件，从连续存储的空洞缺陷过渡到 8 个块号加一级间接索引，最多支持 263 个块。随后用超级块汇总 inode 与块的数量统计，用块描述符记录位图与 inode 表的起始位置。再通过文件类型区分普通文件与目录文件，目录的数据块存放目录项，最终规定 0 号 inode 为根目录，得到与 ext2 基本相同的架构。

## 要点

- 以 1MB 硬盘、1024 个 1KB 块为例，逐步推导文件系统设计。
- 块位图用每一位记录一个块是否被占用，0 号块专门存放块位图。
- 用 128 字节 inode 保存文件大小、时间、权限等元信息，并指向文件数据块。
- inode 位图管理 inode 使用情况，inode 表存放 inode 本体，1 个块可存 8 个。
- 大文件存储先尝试连续存储（有空洞缺陷），改为多块号加一级间接索引，最大 263 个块。
- 超级块汇总 inode 数量、空闲 inode 数量、块数量、空闲块数量等全局统计。
- inode 增加文件类型字段区分普通文件与目录文件，目录数据块存放目录项。
- 规定 inode 表 0 号 inode 为根目录，整体结构与 ext2 基本相同。

## 提炼

> 一句话定位：从零推导一个类 ext2 的极简文件系统

### 分节提炼

- **01 按块读写硬盘**：把硬盘按逻辑分成块，块等于两个物理扇区，即 1024 字节。；假设硬盘只有 1MB，则共有 1024 个块。；存文件就是选一个块放入，先不考虑占用冲突。
- **02 块位图防覆盖**：防止新文件覆盖旧文件，需要记录每个块是否可用。；用 0 号块存块位图，每一位代表一个块的使用情况。；存文件时找第一个为 0 的位，写入后把相应位置 1。
- **03 inode 与元数据**：通过文件名找文件，需要记录文件名与块号的对应关系。；128 字节的 inode 存文件大小、创建时间、权限等元信息。；inode 位图管理 inode 使用情况，inode 表存放 inode，1 块可存 8 个。
- **04 多块与间接索引**：连续存储法只记首块和所需块数，会留下空洞浪费空间。；inode 扩展记录 8 个不连续块号，最大只能表示 8K 文件。；一级间接索引可支持 263 个块，二级间接索引多出 256*256-1 个块。
- **05 超级块与块描述符**：需要全局记录 inode 数量、空闲 inode 数量、块数量、空闲块数量。；超级块放在最开始的块，站在全局视角描述文件系统。；块描述符记录块位图、inode 位图、inode 表的起始块号。
- **06 目录文件与层级**：为支持层级关系，把文件分为普通文件与目录文件。；inode 增加 4 字节文件类型字段区分两者。；目录文件的数据块存指向不同 inode 的结构体。
- **07 目录项优化**：ll 列目录若逐个取 inode 再取文件名和类型，很浪费时间。；把文件名、文件类型放进数据块中的结构体，即目录项。；去掉 inode 中的文件名，给文件所在块数组省空间。
- **08 根目录与 ext2**：规定 inode 表中的 0 号 inode 表示根目录，访问统一从根目录开始。；最终架构与 linux 的经典文件系统 ext2 基本相同。；可对照 ext2 官方文档，或用 mke2fs 生成镜像逐字节拆解学习。

### 带走三句话

1. 文件系统的核心结构就是块位图、inode 位图、inode 表、超级块、块描述符、目录项这几件。
2. inode 只放定长元信息，文件名这类变长数据放到目录项里。
3. 规定 0 号 inode 是根目录，整棵目录树就有了统一入口。
