# 40个优化小技巧，让你的Java 性能提升10倍！

> 一句话定位：40 条 Java 编码性能优化技巧，覆盖对象、容器、同步与资源释放。

## 摘要

本文整理 40 条 Java 编码层面的性能优化技巧，认为性能问题多源于编码习惯而非语言本身。内容覆盖对象与内存：合适场景用单例、少 new 对象并重用、多用基本类型与局部变量、使用 final、尽早释放引用；集合容器：为 HashMap、StringBuffer、Vector 预估初始容量，随机查询用 ArrayList，单线程用 HashMap/ArrayList，用 entrySet 遍历，System.arraycopy 复制数组；计算与结构：缓存 size、移位代替乘除、避免 split 与二维数组；并指出同步、异常、finalize、资源未释放等易踩坑场景。文末强调优化是时间、效率与代码结构的权衡，应结合实际场景取舍。

## 要点

- 性能问题多源于编码习惯而非 Java 语言本身，需养成良好编码习惯。
- 少创建、重用对象，多用局部变量与基本类型，少用二维数组与 split。
- final 方法可被编译器内联，性能平均提升约 50%。
- HashMap、StringBuffer、Vector 应预估并指定初始容量以减少扩容。
- 用移位代替乘除、缓存 size，避免循环内复杂表达式与重复计算。
- 同步、异常、finalize 开销大，应谨慎使用；资源在 finally 中释放。
- 单线程优先 HashMap/ArrayList，慎用 HashTable/Vector 等同步集合。
- 优化是时间、效率与代码结构的权衡，应结合实际场景取舍。

## 提炼

> 一句话定位：40 条 Java 编码性能优化技巧，覆盖对象、容器、同步与资源释放。

### 分节提炼

- **01 合适场合使用单例**：单例适合控制资源使用、控制实例产生、控制数据共享三类场景；并非所有地方都适用单例
- **02 避免随意使用静态变量**：static 引用的对象通常不会被 GC 回收；静态变量生命周期与类同步，可能常驻内存直到程序终止
- **03 少创建 Java 对象**：避免在常调用的方法和循环中 new 对象；尽量重用对象，用基本类型或数组替代对象
- **04 尽量使用 final**：final 类不可派生，其所有方法都是 final；编译器可内联 final 方法，性能平均提高 50%
- **05 尽量使用局部变量**：局部变量保存在栈中，速度较快；静态变量、实例变量在堆中创建，速度较慢
- **06 分清包装与基本类型**：基本类型在栈中处理，包装类型是堆中对象；集合等需对象场景用包装类型，其余提倡基本类型
- **07 慎用 synchronized**：同步开销大，甚至可能造成死锁；synchronize 方法尽量减小，用方法同步代替代码块同步
- **08 不要用 finalize 清理资源**：finalize 清理资源会加重 GC 负担；GC 回收 Young 代内存时易引起应用暂停
- **09 用基本类型代替对象**：String str="hello" 的字符串会进 JVM 字符缓存池；new String 还会额外产生底层 char[] 数组
- **10 单线程优先 HashMap/ArrayList**：HashTable、Vector 使用同步机制降低了性能；无线程安全要求时优先非同步集合
- **11 合理创建 HashMap**：用构造器指定 initialCapacity 与 loadFactor；默认 initialCapacity=16、loadFactor=0.75，扩容很耗性能
- **12 减少变量重复计算**：循环外缓存 list.size()，如先取 len；循环条件避免复杂表达式
- **13 避免不必要的创建**：把对象创建放到真正需要的分支内；避免提前创建用不到的对象
- **14 在 finally 中释放资源**：资源释放放在 finally 中做；finally 总会被执行，确保资源正确关闭
- **15 移位代替除法**：除法代价高，移位更快更有效；a/4 用 a>>2，a/8 用 a>>3
- **16 移位代替乘法**：乘法可替换为左移操作；a*4 用 a<<2，a*8 用 a<<3
- **17 确定 StringBuffer 容量**：默认构造约 16 个字符，超出自增长要重新分配并复制；创建时指定大小可避免容量不够时自动增长
- **18 早释放无用引用**：方法结束时局部引用作用域自然结束，无需显式置 null；执行耗时耗内存操作前把无用引用置 null 可尽早释放
- **19 避免二维数组**：二维数组内存比一维数组多约 10 倍以上
- **20 避免使用 split**：split 支持正则表达式，效率比较低；频繁调用可用 StringUtils.split 或缓存结果
- **21 ArrayList 与 LinkedList**：随机查询尽量用 ArrayList；增删操作用 LinkedList，关键是理解数据结构
- **22 用 System.arraycopy 复制**：System.arraycopy() 比循环复制数组快得多
- **23 缓存常用对象**：用数组或 HashMap 容器缓存常用对象；可用 EhCache、Oscache 等第三方工具缓存
- **24 避免超大内存分配**：问题也可能由分配失败造成；内存块必须连续，堆越满越难找到较大连续块
- **25 慎用异常**：创建异常需收集栈跟踪、为运行时栈做快照，开销大；throw 本身代价不大，捕获开销也不大
- **26 尽量重用对象**：字符串连接用 StringBuffer 代替；生成过多对象会影响程序性能
- **27 不要重复初始化变量**：构造时 Java 已把变量初始化成默认值；需调方法的初始值放 initXXX() 中
- **28 SQL 规范**：Java 内嵌 SQL 尽量使用大写形式；减少 Oracle 解析器的解析负担
- **29 及时释放资源**：数据库连接、I/O 流用完及时关闭释放资源；大对象操作会造成系统大的开销
- **30 避免过量创建对象**：对象过多严重时会导致内存泄漏；对象使用完毕后建议手动设置成 null
- **31 方法同步代替代码块同步**：使用同步机制时优先方法同步
- **32 Try/Catch 放循环外层**：把 Try/Catch 放到循环最外层
- **33 设置 StringBuffer 初始容量**：StringBuffer 默认容量 16，达上限扩容为 2*n+2；设置合理初始容量可避免重建数组并复制
- **34 合理使用 Vector**：Vector 默认容量 10，扩容加倍；删除末尾元素比删除第 1 个元素开销低，删除全部用 removeAllElements()
- **35 用 clone() 代替 new**：new 会调用构造函数链中所有构造函数；clone() 不会调用任何类构造函数
- **36 HashMap 遍历**：用 entrySet 遍历，取得 entry 后直接取 key 和 value；利用散列值取出相应 Entry 做比较
- **37 array 与 ArrayList**：array 效率最高但容量固定；ArrayList 容量可动态增长但牺牲效率
- **38 单线程用非同步集合**：非必要不推荐使用 HashTable、Vector；同步机制会降低性能
- **39 StringBuffer 与 StringBuilder**：StringBuilder 不执行同步，速度更快；StringBuilder 比 StringBuffer 快 10%~15% 但线程不安全
- **40 考虑使用静态方法**：不访问对象外部状态的方法设为静态方法；静态方法调用更快，不需虚拟函数导向表

### 带走三句话

1. 多用局部变量、基本类型和 final，少在循环里 new 对象。
2. 给 HashMap、StringBuffer 预估容量，用移位与缓存 size 减少重复计算。
3. 同步、异常与 finalize 都有代价，按实际场景权衡而非照搬。
