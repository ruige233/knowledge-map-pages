# 凤凰架构

> 一句话定位：周志明《凤凰架构》导读：架构演进、分布式基石与程序员成长

## 摘要

本文是《凤凰架构》开源电子书的导读与读书笔记。作者周志明强调：架构不是被发明而是持续演进的结果；微服务是分布式路线的极致，Serverless 是“不分布式”云端系统的起点。全书分引导篇、五大部分与两个篇外，覆盖架构演进、架构师视角、分布式基石、不可变基础设施与技术方法论。文章重点摘录书中问答：不要轻视不直接产生实践价值的知识，也不要陷入已熟练掌握的技术，并以“内力”“武功”类比原理知识与具体技术；还借《云原生时代，Java 的危与机》讨论 Java 提前编译的困境。

## 要点

- 架构不是被发明出来的，而是持续演进的结果。
- 微服务是分布式系统的极致，Serverless 是“不分布式”云端系统的起点，二者无继承替代关系。
- 共识算法、服务发现、流量治理、网络通信、监控预警共同构成分布式的基石。
- 全书分引导篇、五大部分与两个篇外，并标注了各部分适合的读者类型。
- 共享事务是伪分布式或“阉割版”分布式，鲜有成功案例，不提倡作为常规方案。
- Java 提前编译需放弃动态性，反射、动态代理、字节码生成等能力将不可用。
- 提升能力的两条建议：不要轻视不直接产生实践价值的知识，不要陷入已熟练掌握的技术。
- 架构师应持续编码，原理知识构筑知识框架，决定程序员的能力上限。

## 提炼

> 一句话定位：周志明《凤凰架构》导读：架构演进、分布式基石与程序员成长

### 分节提炼

- **01 全文**：架构是演进结果：微服务→云原生→Serverless，后二者无继承替代关系，别误以为更先进。；分布式的基石为共识算法、服务发现、流量治理、网络通信、监控预警；流量治理与监控预警常随业务发展后补。；Java 提前编译须放弃反射、动态代理等动态能力，框架与 Graal VM 协同适配。；学习建议：重视原理类知识搭框架，具体技术快速掌握也要快速放下，避免陷入熟悉技术。

### 带走三句话

1. 架构不是发明而是演进的结果；微服务与 Serverless 是两条路线，无继承替代关系。
2. 用内力（原理知识）搭框架，用武功（具体技术）解决问题，学完要能快速放下。
3. 重视不直接产生实践价值的知识，别陷入已熟练掌握的技术中不能自拔。
