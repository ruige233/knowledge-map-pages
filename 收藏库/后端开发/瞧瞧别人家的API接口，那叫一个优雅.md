# 瞧瞧别人家的API接口，那叫一个优雅

> 一句话定位：从签名、加密到接口文档的14项优雅API设计实践

## 摘要

本文围绕“如何设计一个优雅的 API 接口”展开，从对接第三方平台的实际场景出发，系统梳理了 14 个设计要点：用签名（参数+时间戳+密钥生成 sign）与 BASE64 加密、IP 白名单保障安全；用限流、参数校验、压测保障稳定；用统一返回值、统一封装异常、请求日志与 traceId 便于维护和定位问题；用幂等设计、限制批量条数、异步处理保证可重复调用与性能；最后通过数据脱敏和完整接口文档降低泄露风险与沟通成本。文章强调把校验、限流、异常封装等能力下沉到 API 网关统一处理，并给出批量接口最多 500 条、签名 15 分钟有效期等具体经验值。

## 要点

- 签名：请求方用“参数+时间戳+密钥”经 md5 生成 sign，网关按相同方式重算并比对，时间戳用于设置有效期（如 15 分钟）。
- 加密：敏感数据（卡号、金额、身份证）拼接密钥后用 BASE64 处理，body 只传一个 data 参数，网关解密后反序列化。
- 安全加固：通过 IP 白名单限制来源，内部服务器被攻破时需加 Web 防火墙（如 ModSecurity）。
- 限流：对 IP、接口、AK/SK 用户三种维度限流，可用 nginx、redis、gateway 实现。
- 参数校验：校验必填、类型、长度、枚举值，Java 用 hibernate Validator 的 @Null/@NotEmpty/@Size/@Max/@Min 等注解。
- 统一返回值与异常：业务异常抛 RuntimeException，由 API 网关捕获并转换成统一结构返回；异常需脱敏封装，避免暴露 SQL、堆栈信息。
- 可重复调用：幂等设计（唯一索引或 redis 存 requestId+参数）、限制批量接口单次最多 500 条、复杂逻辑改 MQ 异步处理。
- 稳定性与协作：上线前用 jmeter 或 apache bench 压测评估 QPS；数据脱敏 + 完整接口文档（命名风格、v1 版本号、字段类型长度）。

## 提炼

> 一句话定位：从签名、加密到接口文档的14项优雅API设计实践

### 分节提炼

- **01 签名**：请求方拼接参数+时间戳+密钥，经md5生成sign，随参数或请求头传给网关；网关用相同规则重算sign并比对，相等放行、不等返回签名错误；时间戳用于设置有效期（如15分钟），防止同一次请求被反复利用
- **02 加密**：银行卡号、金额、身份证等敏感数据不能明文暴露公网；数据拼接密钥后用BASE64处理，可加密多次，body只传一个data参数；网关按约定密钥、加密算法、次数解密并反序列化参数
- **03 IP白名单**：白名单内IP才能请求，否则返回无访问权限；白名单可加在API网关，同时需防内部服务器被攻破后从内网发起请求；可引入ModSecurity等Web防火墙加固
- **04 限流**：并发过高会打挂服务，第三方调用频率不可控，必须限流；三种维度：对IP、对指定接口、对AK/SK用户，分别限制每分钟次数；可用nginx、redis或gateway实现限流
- **05 参数校验**：校验必填、类型、长度、枚举值，把无效请求挡在数据库之前；金额传负数、状态传非法枚举值会造成损失或脏数据；Java用hibernate Validator注解校验，日期/枚举可自定义注解
- **06 统一返回值**：多种返回结构（code/message/data与rt/errorMgt/result混用）会让对接方难理解；网关与业务系统返回结构不一致，异常时各返回各的，不利于维护；业务异常抛RuntimeException，网关捕获后统一转换返回结构
- **07 统一封装异常**：异常不能直接暴露堆栈、数据库信息、错误代码和行数；不法分子可利用返回值中的信息做SQL注入或脱库；网关统一封装为code=500、message服务器内部错误，细节只打印到内部日志
- **08 请求日志**：记录url、参数、请求头、请求方式、响应数据和响应时间；用traceId串联整条请求日志、过滤多余日志；第三方用户需要时可落地mongodb或elastic search并做UI页面开放查看权限
- **09 幂等设计**：第三方可能因业务bug或失败重试，在极短时间内重复请求多次；相同参数重复请求，首次新增数据、后续返回成功但不新增；用数据库唯一索引或redis保存requestId+参数保证幂等
- **10 限制记录条数**：批量接口不限制条数容易超时、变得不稳定；建议单次最多传500条记录，超出直接提示；该参数做成可配置，并提前与第三方协商
- **11 压测**：上线前压测各接口QPS，预估部署节点数；限流阈值可能高于实际处理能力，不压测有风险（如限50实际只能30）；可用jmeter或apache bench做压力测试
- **12 异步处理**：复杂或批量接口同步处理耗时长，改异步提升性能；接口发MQ消息后直接返回成功，由专门消费者异步处理业务；第三方两种取结果方式：我方回调其接口，或轮询状态查询接口（传原接口id集合）
- **13 数据脱敏**：手机号、银行卡号等敏感数据不能直接出外网，易造成隐私泄露；返回数据部分内容用星号代替，如182****887；即使泄露也只泄露一部分，降低风险
- **14 完整的接口文档**：文档应含接口地址、请求方式、参数与字段、返回值与字段、返回码、加密签名示例、demo、额外说明；统一命名风格（如驼峰）、接口地址加版本号v1便于升级；统一字段类型长度（id用Long长度20、status用int长度2）和时间格式（yyyy-MM-dd HH:mm:ss）

### 带走三句话

1. 把签名校验、限流、统一返回值、异常封装等横切能力统一放到API网关，业务系统只专注业务。
2. 安全靠组合拳：签名+加密+IP白名单+异常脱敏+数据脱敏，单点防线被破仍有兜底。
3. 稳定性靠量化与兜底：限流防打挂、压测验QPS、幂等防重复、批量限条数、重逻辑走异步。
