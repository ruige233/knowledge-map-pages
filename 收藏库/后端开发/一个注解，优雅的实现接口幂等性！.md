# 一个注解，优雅的实现接口幂等性！

> 一句话定位：用自定义注解 + AOP + Redis 优雅实现接口幂等性

## 摘要

文章讲解接口幂等性：同一接口重复多次请求与一次请求结果相同。先梳理哪些请求天然幂等：查询天然幂等，删除、更新多数幂等但存在 ABA 及 a=a+1 自增更新例外，插入多数非幂等、可用数据库唯一索引兜底。随后说明为何需要幂等：超时重试、异步回调、消息队列（At least once 投递）都会产生重复请求。实现幂等的关键因素是幂等唯一标识，以及服务端保证该标识只被使用一次。最后给出 Redis 落地方案：自定义 @Idempotent 注解，AOP 切面从 RequestData 取 token，用 Redis delete 判断是否首次请求，首次放行、重复返回“重复请求”，token 由生成接口预存并设 10 分钟有效期。

## 要点

- 幂等指同一接口重复多次请求与一次请求结果相同，生产环境应保证任何接口幂等。
- 查询天然幂等；删除、更新多数幂等但存在 ABA 与 a=a+1 自增更新例外；插入多数非幂等。
- 超时重试、异步回调、消息队列 At least once 投递是重复请求的三大来源。
- 实现幂等的两大关键因素：幂等唯一标识，以及服务端保证该标识只被使用一次。
- 落地方式：自定义 @Idempotent 注解声明 name/type/field，AOP 切面按注解从 RequestData 取 token。
- 用 Redis 的 delete(token) 返回值判断是否首次请求：首次放行执行，重复请求直接返回“重复请求”。
- 调用前先请求 token 生成接口，Redis 保存 token 并设 10 分钟有效期，再携带 token 调用业务接口。

## 提炼

> 一句话定位：用自定义注解 + AOP + Redis 优雅实现接口幂等性

### 分节提炼

- **01 什么是幂等性**：幂等：同一接口重复多次请求与一次请求产生相同结果；生产环境应保证任何接口都幂等，需要严谨设计
- **02 哪些请求天然幂等**：查询天然幂等；删除多数幂等，ABA 场景除外；更新多数幂等，但 update a=a+1 自增更新非幂等；插入多数非幂等，可用数据库唯一索引保证不重复
- **03 为什么需要幂等**：从三个场景说明为什么需要保证幂等；超时重试、异步回调、消息队列都会产生重复请求
- **04 超时重试**：请求实际已发出但响应超时，重试会让服务端重复执行；请求方重新发起请求时，被请求方需保证幂等
- **05 异步回调**：异步回调是提升系统接口吞吐量的常用方式；异步回调类接口必须保证幂等
- **06 消息队列**：Kafka/RocketMQ/RabbitMQ 采用 At least once 原则，允许重复消息；消息队列不保证无重复，消费者需保证处理逻辑幂等
- **07 实现幂等的关键因素**：幂等唯一标识（幂等号/幂等令牌/全局ID），一般由客户端生成；服务端确保唯一标识只被使用一次，如数据库唯一索引
- **08 注解实现幂等性**：演示一种利用 Redis 实现幂等的方案；核心流程：注解标记 → AOP 拦截 → token 判定
- **09 自定义注解**：定义 @Idempotent 注解，含 name、field、type 三个属性；name 指定从哪个参数取值，field 指定取哪个属性，type 指定参数类型
- **10 统一的请求入参对象**：RequestData<T> 统一封装 Header（含 token）与 body；示例 Order 实体含 orderNo 字段
- **11 AOP 处理**：@Pointcut 拦截带 @Idempotent 注解的方法，@Around 环绕处理；反射取注解的 field/name/type，从 RequestData 取 token；Redis delete(token) 为 true 则放行，否则返回“重复请求”
- **12 Token 值生成**：IdempotentStorage 接口定义 save/delete，Redis 实现保存 10 分钟；IdGeneratorUtil 用 UUID 生成 token，控制器提供 token 获取接口
- **13 请求示例**：调用前先申请 token，携带 token 再请求业务接口；@Idempotent(name = "requestData", type = RequestData.class, field = "token") 标记 saveOrder；第一次请求成功，第二次请求失败（重复请求）

### 带走三句话

1. 幂等的本质是同一请求重复多次与执行一次结果一致，实现关键是唯一标识 + 标识只用一次。
2. 落地套路：@Idempotent 注解声明取 token 的参数，AOP 拦截后用 Redis delete 判定首/重复请求。
3. 调用前先申请 token 再请求业务接口，重复请求直接返回“重复请求”，不再执行业务逻辑。
