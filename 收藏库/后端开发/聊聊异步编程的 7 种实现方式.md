# 聊聊异步编程的 7 种实现方式

> 一句话定位：一文梳理 Java 异步编程的七种实现方式

## 摘要

文章梳理 Java 异步编程的七种实现方式：继承 Thread 直接启动；Java 1.5 的 Callable/Future 取结果但 get() 阻塞；FutureTask 兼具 Runnable 与 Future 能力、CAS 保线程安全；JDK 1.8 的 CompletableFuture 以回调实现异步非阻塞；SpringBoot 的 @Async 以方法体为边界异步执行；Spring 事件机制默认同步、需自定义 SimpleApplicationEventMulticaster 并设 TaskExecutor 才异步；消息队列是天然异步架构。核心思路是串行变并行、减少线程等待，提升高吞吐性能并降低时延。

## 要点

- 异步编程用多线程把串行改并行，减少线程等待，提升高吞吐场景性能并降低时延。
- 继承 Thread 是最简单异步方式，频繁创建销毁浪费资源，应改用线程池。
- Java 1.5 的 Callable/Future 能在任务完成后取结果，但 get() 会阻塞。
- FutureTask 兼具 Runnable 与 Future 能力，线程安全由 CAS 保证。
- JDK 1.8 的 CompletableFuture 以回调实现异步非阻塞，提供约 50 种 API。
- SpringBoot 的 @Async 以方法体为边界异步执行，需 @EnableAsync 且类须为 Spring bean。
- Spring 事件机制默认同步阻塞，自定义 SimpleApplicationEventMulticaster 并设 TaskExecutor 才异步。
- 消息队列是天然异步架构，借助中间件可高效实现异步编程。

## 提炼

> 一句话定位：一文梳理 Java 异步编程的七种实现方式

### 分节提炼

- **01 继承 Thread 与线程池**：继承 Thread 类是最简单的异步线程创建方式，用 start() 启动；频繁创建销毁 Thread 浪费系统资源，应改用线程池；业务逻辑封装到 Runnable 或 Callable 交由线程池执行
- **02 Callable 与 Future**：Java 1.5 起 Callable 和 Future 可在任务完成后获取执行结果；Future 提供取消任务、查询是否完成、获取结果等方法；get() 会阻塞直到任务执行完毕才返回，另有带超时的重载
- **03 FutureTask**：FutureTask 实现 RunnableFuture，可提交线程池执行也可直接 Thread 执行；封装 Callable 和 Runnable，既能执行又能获取结果；线程安全由 CAS 保证
- **04 CompletableFuture**：JDK1.8 提供，基于异步函数式编程；通过回调处理计算结果，异步非阻塞、性能优于 Future；提供约 50 种 API 处理串行、并行、组合与错误
- **05 @Async 注解**：@EnableAsync 启用异步注解，@Async 标记异步方法；以方法体为边界，方法内逻辑整体异步执行；可用 @Async("线程池名") 指定自定义线程池
- **06 Spring 事件机制**：ApplicationEvent 与 ApplicationListener 本质是观察者模式；默认同步阻塞，生产端与消费端同线程执行；自定义 SimpleApplicationEventMulticaster 并设 TaskExecutor 可实现异步
- **07 消息队列**：消息队列是天然异步架构，高吞吐、低时延；角色含生产者、消息队列、消费者，消费分点对点与发布订阅；常见框架有 RabbitMQ、Kafka、RocketMQ、ActiveMQ、Pulsar

### 带走三句话

1. 异步的核心是串行变并行、减少线程等待，以提升高吞吐场景的吞吐量并降低时延。
2. 选型按需递进：Thread 最简单，Future/FutureTask 取结果，CompletableFuture 非阻塞组合，MQ 跨进程解耦。
3. Spring 的 @Async 与事件机制要留意 bean 托管与默认同步这两个易错点。
