引言

java中OOM又分很多类型；比如：堆溢出（“java.lang.OutOfMemoryError: Java heap space”）、永久带溢出（“java.lang.OutOfMemoryError:Permgen space”）、不能创建线程（“java.lang.OutOfMemoryError:Unable to create new native thread”）等很多种情况。 测试会发现使用堆的数量，突然间急剧下滑！这代表这一点，当一个线程抛出OOM异常后，它所占据的内存资源会全部被释放掉，从而不会影响其他线程的运行！ 其实发生OOM的线程一般情况下会死亡，也就是会被终结掉，该线程持有的对象占用的heap都会被gc了，释放内存。因为发生OOM之前要进行gc，就算其他线程能够正常工作，也会因为频繁gc产生较大的影响。

最近网上出现一个美团面试题：“一个线程OOM后，其他线程还能运行吗？”。我看网上出现了很多不靠谱的答案。这道题其实很有难度，涉及的知识点有jvm内存分配、作用域、gc等，不是简单的是与否的问题。

由于题目中给出的OOM，java中OOM又分很多类型；比如：堆溢出（“java.lang.OutOfMemoryError: Java heap space”）、永久带溢出（“java.lang.OutOfMemoryError:Permgen space”）、不能创建线程（“java.lang.OutOfMemoryError:Unable to create new native thread”）等很多种情况。

本文主要是分析堆溢出对应用带来的影响。

结论

答案：其他线程还能运行

示例中 Thread-0 抛 Java heap space 后，Thread-1 仍持续输出；OOM 线程堆内存被释放，不影响其他线程运行。

概念对比

OOM 常见类型对比

堆溢出 Java heap space、永久代溢出 Permgen space、无法创建新线程 Unable to create new native thread 等，本文聚焦堆溢出。

代码模式

线程堆溢出复现

while(true) 中 new byte[1024*1024*1] 并 list.add(b)，每秒休眠，持续分配直至抛出 OutOfMemoryError。

数据

结果日志

14:42:05~14:42:25 间堆使用量急剧下滑；Thread-0 抛错后 Thread-1 持续输出 14:42:20/21/22。

易错点

OOM 前会频繁 GC

发生 OOM 前会进行 GC，即使其他线程正常工作，也会因频繁 GC 产生较大影响，不能忽视。

结论

栈溢出结论一致

本文只演示堆溢出；栈溢出结论相同，可自行测试验证。

带走三句话
  1. 单个线程 OOM 只会终结该线程，其堆内存被 GC 回收，不影响其他线程运行。
  2. OOM 分堆溢出、永久代溢出、无法创建新线程等类型，需先区分场景再下结论。
  3. OOM 前会触发 GC，其他线程虽能运行，也会受频繁 GC 拖累。
