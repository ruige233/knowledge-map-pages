01简单使用

本节提炼
  • Spring Validation 是 hibernate-validation 的二次封装，底层由 Hibernate Validator 执行校验。
  • spring-boot 2.3.x 起需手动引入 hibernate-validator 依赖。
  • requestBody 用 DTO+@Validated/@Valid；GET 平铺参数需类上加 @Validated 且入参声明约束注解。
  • 校验失败分别抛 MethodArgumentNotValidException 与 ConstraintViolationException，用 @RestControllerAdvice 统一处理。
  • spring-boot 2.3.x 以上忘记手动引入 hibernate-validator 依赖会导致校验不生效。
Java API规范(JSR303)定义了Bean校验的标准validation-api，但没有提供实现。hibernate validation是对这个规范的实现，并增加了校验注解如@Email、@Length等。

Spring Validation是对hibernate validation的二次封装，用于支持spring mvc参数自动校验。接下来，我们以spring-boot项目为例，介绍Spring Validation的使用。

对于web服务来说，为防止非法参数对业务造成影响，在Controller层一定要做参数校验的！大部分情况下，请求参数分为如下两种形式：

  • POST、PUT请求，使用requestBody传递参数；
  • GET请求，使用requestParam/PathVariable传递参数。

下面我们简单介绍下requestBody和requestParam/PathVariable的参数校验实战！

requestBody参数校验

POST、PUT请求一般会使用requestBody传递参数，这种情况下，后端使用DTO对象进行接收。只要给DTO对象加上@Validated注解就能实现自动参数校验。比如，有一个保存User的接口，要求userName长度是2-10，account和password字段长度是6-20。

本节提炼
  • 同一 DTO 多个方法校验规则不同，用分组校验 groups 区分。

  • requestBody 校验在 RequestResponseBodyMethodProcessor.resolveArgument() 的 validateIfApplicable() 中触发。
  • 方法级校验基于 AOP：MethodValidationPostProcessor 注册切面、MethodValidationInterceptor 织入增强。

方法级别的参数校验实现原理

上面提到的将参数一个个平铺到方法参数中，然后在每个参数前面声明约束注解的校验方式，就是方法级别的参数校验。

概念对比

@Valid 与 @Validated

requestBody 场景二者可混用：源码中校验注解以 Valid 开头或直接标注 @Validated 即触发校验。

概念对比

两类校验异常

requestBody 抛MethodArgumentNotValidException，GET参数抛ConstraintViolationException

数据

GET 参数个数阈值

GET 参数超过 6 个推荐改用 DTO 接收，否则平铺到方法入参并逐个声明约束注解。

数据

spring-boot 2.3.x 分界

spring-boot 小于 2.3.x 自动带 hibernate-validator；大于 2.3.x 需手动引入依赖。

代码模式

DTO+@Validated 校验

DTO 字段加 @NotNull/@Length，方法参数加 @Validated，失败抛 MethodArgumentNotValidException。

代码模式

自定义校验注解

自定义注解标 @Constraint(validatedBy=EncryptIdValidator.class)，校验器实现 isValid。

代码模式

ValidationList 包装集合

包装 List 实现 List<E>，字段加 @Delegate @Valid 并重写 toString，JSON 数组才能逐项校验。

代码模式

Fail Fast 配置

注入 Validator Bean 时 .failFast(true)，一旦校验失败立即返回而非校验完所有字段。

易错点

嵌套对象忘加 @Valid

嵌套校验时 DTO 对应对象字段必须标记 @Valid，否则子对象约束不生效。

易错点

直接 List 接收 JSON 数组

直接 Collection 的 List/Set 接收 JSON 数组，参数校验不会生效。

概念对比

分组校验 Save/Update

同一 DTO 不同方法规则不同，约束注解 groups 区分：userId 仅 Update 组要求 @Min。

结论

底层统一结论

requestBody 校验与方法级校验最终都调用 Hibernate Validator，Spring Validation 仅做封装。
