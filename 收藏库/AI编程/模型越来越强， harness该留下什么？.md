# 模型越来越强， harness该留下什么？

> 一句话定位：模型变强后，harness 该删能力型脚手架、留组织验收与授权边界

## 摘要

本文基于 tdsql-harness 瘦身实践（根指令删 61%、skills 砍 40%），回答模型变强后 harness 该留什么。核心判断：冗余指令在弱模型时代只浪费 token，今天会缩小搜索空间、被字面执行、导致过度触发，已成净损失。写作要点：删掉读代码就能得到的内容，把禁令换成判据，放开路径但收紧验收，先建评测再写内容，能沉降到工具层就别留指令层。harness 分四层：L0/L1 补能力会过期，L2 迁移到工具层，L3 验收与授权永不内化，这是自建 harness 的立足点。

## 要点

- 行业级转向：Anthropic 与 OpenAI 独立收敛到“减法”，为旧模型写的指令在新模型上会主动造成质量损失。
- 冗余从“中性浪费”变“负数”：缩小搜索空间、被字面执行、导致过度触发，官方建议删除而非改写。
- 写作五道关卡：该不该写→怎么表达→给多大自由度→怎么验证→写完往哪里退。
- 删除判据：agent 读代码库能找到的信息就删；无会话记忆的 agent 读到行为不变也删。
- 放开路径、收紧验收：目标、成功判据、约束写死，路径留给模型；判据必须可机械判定。
- 先建评测再写内容：内容“刚好够”由评测反推，这也是敢删 80% 的底气。
- 四层归属：L0/L1 补能力会过期，L2 迁移到工具层，L3 永不内化；自建 harness 立足 L2/L3。
- 自主度上界等于验证能力：能廉价可靠验证多少，才给多少自主度。

## 提炼

> 一句话定位：模型变强后，harness 该删能力型脚手架、留组织验收与授权边界

### 分节提炼

- **01 正在发生什么**：两家厂商独立收敛到“减法”：Anthropic 删掉系统提示词 80% 以上，评测无损失。；冗余已从中性变负数：过度规定缩小搜索空间、被字面执行、导致过度触发，应删除而非改写。；四件转变：规则→判据、前置上下文→渐进披露、示例→接口设计、markdown 规格→可执行引用物。；prefill 从 Claude 4.6 起被 API 移除：脚手架消失是因它防御的问题不存在了。
- **02 harness 与 skill 该怎么写**：该不该写：agent 读代码库能找到的就删；复述默认行为的 skill 只增上下文不增价值。；怎么表达：穷举禁令换成判据，MUST/NEVER 只留给真正的不变量（如不可逆动作）。；自由度：放开路径、收紧验收；目标、成功判据、约束写死，路径留给模型。；验证与沉降：先建评测再写内容，“刚好够”由评测反推；能写成 linter/测试/CI 就别留指令。
- **03 什么值得留下**：总纲：每个组件都编码“模型做不到什么”的假设，真正的工作是识别赌注是否到期。；四层归属：L0/L1 补能力会过期，L2 迁移到工具层，L3 永不内化；立足点 L2/L3。；L3 长存两条理由：信息不可达（价值排序/私有 context/主观 oracle）与责任不可转移。；结构性偏差不消失：同模型自评过度宽容，独立 reviewer 与跨模型校验价值不衰减。
- **04 变的和不变的**：会过期的判别式：凡为补模型能力缺口而写的都会过期（理由如“模型记不住/不会主动做/容易漏”）。；不会过期的三件事分属 L2/L3：一种资产每次升级减记，另一种越积越厚无人能替。；四个动作：写清每条防的失败、每代际做到期审计、力气挪到 L2/L3、能沉降就沉降。
- **05 参考来源**：罗列 Anthropic、OpenAI、Addy Osmani 三方一手来源。；全部可直接访问核对，覆盖 prompting 指引与 harness 设计文章。

### 带走三句话

1. 删掉复述模型默认行为和读代码就能得到的内容，把力气投到验收标准与授权边界上。
2. 凡补模型能力缺口的规则都会过期，写清每条规则防的具体失败，让它可检测、可淘汰。
3. 把能写成 linter/测试/CI 的约束沉降到工具层，指令文件才会越修越短。
