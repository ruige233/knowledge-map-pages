# 一文讲透确定性Harness

> 一句话定位：用确定性 Harness 把概率性 LLM 输出约束为可交付、可追溯的确定性结论

## 摘要

高风险决策中，LLM 输出是概率性的，结论却必须确定性、可解释、可追责。本文提出「确定性 Harness」：把策略文档拆成阶段化代码流水线，用 FlowTracer 为每步输入输出分支留痕，用 IsFinal 提前终止，用统一网关加缓存稳住外部依赖。以工单审核为例：九个阶段、几十个条件分支、六步顺序校验，判错即客诉，LLM 只是可插拔的判断单元。实践效果：单均耗时从 2-3 分钟压到 20-40 秒。核心判断：模型是商品，Harness 才是护城河。

## 要点

- 「模型是商品，harness 才是护城河」——让结论可负责的是模型之外那层工程纪律。
- 确定性 Harness 四件事：阶段化编排、FlowTracer 全链路留痕、IsFinal 提前终止、统一网关与缓存。
- LLM 在 Harness 里是可随时插拔的判断单元，不是主角。
- 高风险审单三大挑战：黑盒不可解释、循环失控、证据链断裂，通用方案接不住。
- 阶段函数签名统一 + goto 标签路由，让几十个分支保持线性可读主干。
- FlowTracer 用 BeginStage/SetInput/SetBranch/SetOutput/EndStage 留档，debug 关闭时零开销。
- 工单平均耗时从 2-3 分钟压缩至 20-40 秒，提前结单 3 秒出结论。
- 高风险+复杂分支+必须可解释选 Harness；纯生成、黑盒探索、轻量任务不需要。

## 提炼

> 一句话定位：用确定性 Harness 把概率性 LLM 输出约束为可交付、可追溯的确定性结论

### 分节提炼

- **01 背景与痛点**：「接个 LLM 就够」是错觉，模型答案前还有主链路与一堆能力分支；工单审核九阶段、几十分支、六步顺序校验，单判错即客诉；三大痛点：黑盒不可解释、循环失控、证据链断裂
- **02 三大挑战**：黑盒不可解释：纯 LLM 给不出可追溯到规则、证据、数据点的理由；循环失控：模型反复重试，接口开销实打实，出结论慢；证据链断裂：模型、工具、人工、缓存混在一起，无法回放判断轨迹；本质：LLM 概率性输出与确定性结论之间有先天鸿沟
- **03 Harness 定位**：模型是商品，harness 才是护城河；四设计：编排、留痕、终止、网关，回答路径/证明/边界/依赖四个问题；四个设计环环相扣，缺一个闭环就断
- **04 技术拆解**：阶段化编排：阶段函数签名统一，goto 标签保持线性主干；FlowTracer 用 BeginStage 开档、记输入/分支/输出、EndStage 收尾；IsFinal 短路：声明式 handler 列表，能下结论就 break；统一网关：CallLxAtomAPIs MD5 封装，TaskID 落 Redis 100h 缓存
- **05 实战案例**：案例1：几十分支策略文档翻译成阶段函数+标签路由，DebugTrace 逐条回放；案例2：基本信息不过即 IsFinal 提前结单，3 秒拿驳回结论
- **06 效果与方法论**：量化提效：单均耗时 2-3 分钟 → 20-40 秒；能力下沉：审核员看结论+回放，开发只写阶段业务判断；反直觉取舍：单步失败不阻断、留痕默认关闭、刻意用 goto
- **07 演进与边界**：演进：挂载可插拔 LLM、主动巡检告警、可控写入走 L1/L2/L3；边界：纯生成、100% 黑盒、轻量单次任务不需要 harness；判断：结论需不需要对某个人、某条规则负责
- **08 结语**：四件事没有一件是为了让模型更聪明；让 Agent 敢对结论负责的，是模型之外那层纪律

### 带走三句话

1. 高风险决策里真正稀缺的不是更聪明的模型，而是让 LLM 敢上线的工程纪律。
2. 要不要上 Harness 只问一句：这个结论需不需要对某个人、某条规则、某次检查负责？
3. 编排、留痕、终止、网关四设计互为闭环：少留痕查无对证，少终止白跑全流程，少网关被上游拖垮。
