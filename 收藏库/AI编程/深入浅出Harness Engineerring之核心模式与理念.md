# 深入浅出Harness Engineerring之核心模式与理念

> 一句话定位：拆解Claude智能体的核心模式：从Claude Code到Hermes

## 摘要

本文拆解Claude智能体的核心模式与理念。Claude Code篇讲上下文管理（持久化指令、分层记忆、渐进式压缩等）与工作流编排、工具权限、自动化钩子。Managed Agents篇以宠物与牲畜哲学区分Session与Harness/Sandbox，实现三件套解耦；Session只追加可重放，凭证经保险库与代理调用，首Token延迟降60-90%。Hermes篇展示五段式循环与L1-L5记忆，靠技能手册、向量语义检索与用户建模持续进化。

## 要点

- 持久化指令文件让规则跨会话复用，但需随项目更新维护，否则会误导智能体。
- 上下文管理五种模式：持久化指令、作用域组装、分层记忆、做梦整理、渐进式压缩，各有代价。
- 工作流与编排核心是“分离”：探索-规划-行动循环、上下文隔离子智能体、分支-合并并行。
- 工具与权限靠渐进式扩展、命令风险分类、单用途工具设计，降低出错与安全风险。
- 智能体三件套解耦：Claude负责推理，Harness驱动循环，Sandbox隔离执行；Session只追加、可重放。
- 凭证永不进沙盒：保险库+代理架构遵循最小权限，外部调用可审计、凭证可轮换。
- 多智能体协作有“多脑一手、一脑多手、多脑多手”三种模式，由三组件解耦自然支持。
- Hermes五段式循环加五层记忆（L1-L5），靠技能手册、向量检索与用户建模持续进化。

## 提炼

> 一句话定位：拆解Claude智能体的核心模式：从Claude Code到Hermes

### 分节提炼

- **01 Claude Code 工程实践**：上下文五种模式按需组合，每种都有维护或可靠性代价。；编排核心是“分离”，循环、子智能体、并行各适配不同任务。；工具按需加载、风险分级、单用途封装，提升安全与可控性。；确定性生命周期钩子由系统强制关键流程执行，不依赖模型记忆。
- **02 Claude Managed Agents 架构**：Session是宠物，Harness和Sandbox是牲畜：前者持久保存，后者可随时重建替换。；三件套解耦：Claude负责推理，Harness驱动循环，Sandbox隔离执行，Harness本身无状态。；Session只追加日志，核心接口仅emitEvent()与getEvents()，天然支持重放与恢复。；凭证经保险库+代理按需获取，永不进沙盒；解耦后首Token延迟可降60-90%。
- **03 Hermes 会进化的智能体**：Hermes五段式循环：规划→执行→观察→学习→适应，形成进化闭环。；五层记忆从短期便利贴到长期工作日志，复杂任务后自动生成SKILL.md。；L3语义记忆用向量检索，语义相近文本向量位置接近，支持模糊匹配。；L4用户建模用辩证式更新，不一次定终身，持续修正对用户的理解。

### 带走三句话

1. 把智能体拆成大脑、双手、工作台，状态全部落进只追加的Session，才能随时重启、恢复与替换。
2. 上下文管理是一套权衡：持久化、分层、压缩都要付出维护、复杂度或信息损失代价。
3. 安全靠架构而非约定：凭证放保险库、经代理按需取用，永不让凭证进入沙盒。
