# 一个文件让 AI Coding 效率翻倍：AGENTS.md 实践指南

> 一句话定位：以管控系统为样本，讲透 AGENTS.md 的写法与五项落地工程实践

## 摘要

文章以 Spring Boot + React 管控系统为样本，讲解如何写好并落地 AGENTS.md。从 CLAUDE.md 普及到各家各自为政，2025 年统一为事实标准，截至 2026 年初超 6 万开源项目使用。没有 AGENTS.md 时有四类痛点：前后端上下文割裂、不认识私域组件、不知道项目规矩、不会启动自测。核心理念是把 AGENTS.md 当「地图」而非「手册」，只放必需信息与硬性规则。文中给出五项实践：仓库聚合、统一环境配置、curl 验证闭环、自动化检查、参考项目引入。

## 要点

- AGENTS.md 是给 AI 看的项目指令文件，相当于「AI 的 README」，包含构建命令、编码规范、测试与安全注意事项。
- 从 CLAUDE.md 普及到各家工具各自为政，2025 年统一后 AGENTS.md 成为事实标准，超 6 万个开源项目使用。
- 没有 AGENTS.md 的四类痛点：前后端上下文割裂、AI 不认识私域组件、不知道项目规矩、不会启动与自测。
- 核心理念是「地图而非手册」：渐进式披露，只写 AI 理解全貌的必需信息和硬性规则，细节靠文档链接。
- 五项实践：仓库聚合（monorepo）、统一环境配置、curl 验证闭环、自动化检查、参考项目引入。
- 验证闭环要求「跑通接口才算完」：后端 curl 验证接口，前端 Agent Browser 验证页面，支撑夜间自主执行。
- 规则要有执行力：分层依赖用 lint 脚本自动检查，错误信息按 WHAT+WHY+HOW 输出。
- 用 /init 或 harness-creator 起步，以 bad case 驱动迭代、团队共建，并标注文件目标读者。

## 提炼

> 一句话定位：以管控系统为样本，讲透 AGENTS.md 的写法与五项落地工程实践

### 分节提炼

- **01 前言**：全文围绕「怎么写好一份 AGENTS.md」展开；先介绍前世今生，已了解者可跳过；以管控系统（Spring Boot + React）为实践样本
- **02 AGENTS.md 是什么？**：AGENTS.md 是给 AI Agent 看的项目指令，类比「AI 的 README」；官方建议：根目录创建，写项目概述、构建测试命令、代码风格、安全注意；monorepo 可放嵌套 AGENTS.md，Agent 读最近的那个；格式无强制要求，就是标准 Markdown
- **03 前世今生**：概念由 Anthropic 的 CLAUDE.md 普及，运行时自动加载注入请求；各工具曾各自为政，2025 年统一为 AGENTS.md 事实标准；超 6 万开源项目使用，Claude Code 用软链接 ln -s 兼容
- **04 没有 AGENTS.md 的日子**：四类痛点：前后端上下文割裂、不认识私域组件、不知道项目规矩、不会启动自测；私域组件源码是最准确的文档，永不落伍；根源是项目知识存在人脑而非 AI 能读到的地方
- **05 核心理念**：第一原则是渐进式披露：AGENTS.md 是约 200 行的导航地图；什么都重要时什么都不重要，巨文件会稀释 AI 注意力；模型足够聪明，只需告诉它文档在哪、源码在哪、何时去看
- **06 写进的内容**：只写两类：AI 理解项目全貌的必要信息、违反会直接出错的硬性规则；必要信息含技术栈、仓库结构、核心模块、分层架构；硬性规则含编码规约、命名约定、禁止项
- **07 不写的内容**：详细内容放 docs 链接：architecture、development、ref-* 等；判断标准：不知道会写错代码放 AGENTS.md，不够好则放详细文档
- **08 实践一：仓库聚合**：演进路径：三仓分离 → 脚本聚合(setup-repos.sh) → monorepo；frontend/ 目录已 gitignore，不影响后端 CI/CD；monorepo 让 AI 同窗口看到 Controller 与前端 API 调用，实现全栈编码；用户手册入仓，AI 可基于代码变更同步更新文档
- **09 实践二：统一环境配置**：环境变量统一放 ~/.<project>_env，启动脚本自动 source；放 ~ 下避免误提交 Git，AGENTS.md 写明 env 优先级；一键启动脚本封装 JDK 检测、优雅关闭、健康检查
- **10 实践三：验证闭环**：curl 规范：每个 curl 独立执行、临时文件中转、token 模板化；用临时文件中转避免 zsh 管道+方括号 glob 报错；后端 curl 验证接口，前端 Agent Browser 验证页面渲染；验证闭环是夜间自主执行的前提
- **11 实践四：自动化检查**：分层依赖规则 L0-L5，lint 脚本扫描 import 检查依赖方向；错误信息按 WHAT+WHY+HOW 输出，AI 可直接照 HOW 修复；Makefile 统一质量检查入口（lint-arch 等）
- **12 实践五：参考项目引入**：用 git submodule 引入 Higress、Nacos、私域组件等源码；源码永不落伍，ref-* 文档当「地图」辅助定位；闭源组件与内部项目引入源码最有效，文档不能替代源码
- **13 为什么选择 AGENTS.md**：团队工具分散（Qoder、Cursor、灵码、Kiro、Claude Code）；足够通用、零配置、降低维护负担、软链接兼容 Claude Code；核心规则收敛到 AGENTS.md 一个入口，工具专属配置作补充
- **14 编写模板**：9 章节模板：概述/快速命令/前后端架构/关键约定/验证/质量检查/参考项目/文档导航；前 10 行必须让 AI 建立项目心智模型；建议控制在 200 行以下
- **15 实施建议**：用 /init 或 harness-creator 一键起步，再按项目特点逐步优化；bad case 驱动迭代：AI 犯错→补规则→判断放全局还是 docs/；规则优先级：能自动化检查 > 写 AGENTS.md > 口头约定；标注文件目标读者，README.md 与 AGENTS.md 互补不合并
- **16 项目全貌**：全景图汇总 AGENTS.md、README、Makefile、scripts、docs 等目录；关键约定：BusinessException、统一响应、禁止跨层依赖等
- **17 总结**：本质：用最小上下文成本换 AI 最大的项目理解；关键是写得准而非写得多，堵住 AI 最易犯错处；维护 AGENTS.md 本身就是团队知识沉淀

### 带走三句话

1. 把 AGENTS.md 写成约 200 行的地图：只放 AI 不知道会写错代码的必需信息与硬性规则，细节交给文档链接。
2. 让验证闭环跑起来：统一环境配置与一键启动脚本，配合 curl/浏览器验证，Agent 自主完成改→构建→启动→验证。
3. 规则要有执行力：分层依赖等关键约定配 lint 自动化检查，错误信息按 WHAT+WHY+HOW 输出供修复。
