# Harness不是目的，知识才是护城河 —— 一个AI工程交付团队的知识沉淀实践

> 一句话定位：Harness工作流只是管道，团队知识的沉淀才是真正护城河

## 摘要

本文提出：构建 Harness 工作流不是目的，团队知识沉淀才是技术护城河。作者回顾 Harness 三支柱框架，指出知识管理是核心能力而非附属品，工作流只是管道，领域知识是复利资产。AI Team 系统采用三维正交知识架构——五层存储 × 五种类型 × 三级成熟度，配套自动衰减与 Lint 治理；知识库以独立 Git 仓库共建共享，贡献暂存+异步合并。工作流在 INIT 注入、执行中按需查询、ARCHIVE 自动提取并提升条目，结合三级渐进式索引与查询预算控制上下文膨胀，并以远程操控跨设备接管保障闭环 7×24 流转。

## 要点

- Harness Engineering 强调引导约束模型能力而非提升模型本身，三大实践侧重各异。
- 核心技术护城河不在模型，而在垂直领域知识的沉淀；工作流只是管道，知识才是活水。
- 知识管理是 Harness 核心能力：上下文工程、架构约束、持续治理三支柱均包含知识机制。
- 用五层存储 × 五种类型 × 三级成熟度三维正交体系组织知识，并支持向上提升与自动衰减。
- 团队知识库采用独立 Git 仓库共建共享，贡献暂存+异步合并，自动解决大部分冲突。
- 工作流服务知识沉淀：INIT 注入、各阶段按需查询、ARCHIVE 提取并自动提升知识条目。
- 三级渐进式索引 + 查询预算 + 引用追踪闭环，让知识消费精准并控制上下文膨胀。
- 远程操控与跨设备接管突破在场依赖，文件系统即状态机保障 7×24 流转与知识闭环。

## 提炼

> 一句话定位：Harness工作流只是管道，团队知识的沉淀才是真正护城河

### 分节提炼

- **01 热潮与核心论断**：Harness 源自“马具”隐喻：强调引导约束 AI 能力，而非增强模型本身。；三大实践侧重：Codex 人机交互协议、Cursor 多 Agent 协同、Claude Code 长时运行稳定性。；核心论断：护城河不在模型，而在垂直领域知识沉淀；工作流是管道，知识是活水。
- **02 三支柱与知识位置**：三支柱：上下文工程、架构约束、持续治理，分别包含记忆、编排、质量门禁等要素。；知识检索注入、长短期记忆、知识生命周期、自动衰减均在三支柱中。；知识管理本身是 Harness Engineering 的核心能力，而不是附属品。
- **03 知识为何比工作流重要**：工作流可替换、知识可累积；如“广告预算高并发超扣需 Redis+Lua 原子性”恒有价值。；没有知识沉淀的工作流是一次性的：坑照踩、架构决策重复推导。；知识分散点/因果/时空三类，是团队复利资产，proven 条目让新人站在前人肩上。
- **04 三维知识分层架构**：三维正交：存储层 Layer 0-P/0-T/1/2/3、类型 model/decision/guideline/pitfall/process、成熟度 draft→verified→proven。；知识可向上提升：项目知识若跨项目通用，自动提升到 Layer 1 或 Layer 2。；自动衰减：proven 12 个月未引用降 verified，verified 6 个月降 draft，draft 持续未引用归档。
- **05 知识库共建共享**：知识库是独立 Git 仓库，作为单一事实来源，获得跨项目共享、生命周期独立、权限独立。；三种角色：maintainer 裁决、contributor 工作流贡献、reader 只消费。；贡献模式借鉴区块链：log.md 只追加、evidence 可溯源、maturity 多人验证提升。；冲突解决：纯新增/证据追加/成熟度提升自动合并，内容矛盾交 maintainer 裁决。
- **06 工作流服务知识沉淀**：16 阶段状态机每阶段与知识流动关联，三通道沉淀：/flow-import 冷启动、/flow-run 每次需求。；三关键时刻：INIT 注入知识、各阶段按需查询、ARCHIVE 由 @archiver 提取并判定提升。；各阶段按查询预算聚焦不同知识类型，避免上下文膨胀。
- **07 三级索引与查询预算**：从“推送”转向“主动查询”，避免信息过载与不精准。；三级渐进式索引：全景目录~50行、分类清单~100-300行、完整条目~50-200行，按需逐层深入。；knowledgeReferences 引用追踪形成闭环，被引用提升、未引用自动衰减。
- **08 突破在场依赖**：在场依赖：一天能坐工位操控 Agent 常不足 4 小时，离开即暂停，效率至少折半。；解法：Hapi 内网版远程操控+跨设备接管，办公网下用手机/浏览器接管开发机 AI 会话。；文件系统即状态机使暂停不丢进度，但暂停过久拉长交付周期、降低知识沉淀时效。；架构启示：状态持久化、断点恢复、异步审批、通知触达。
- **09 落地经验与立场**：冷启动：多源收集 + 渐进导入（初始 draft，置信度 0.5-0.6）+ import-state.json 断点恢复。；Lint 机制治理知识膨胀：检查索引/孤儿/矛盾/过时/重复/成熟度，支持自动修复与归档。；Big Model vs Big Harness 找平衡点：模型提升保持开放但不能替代领域知识，知识工程回报确定。；文件系统即状态机带来可见性、可版本化、可迁移性、IDE 原生。
- **10 总结与展望**：六个实践结论：分层管理、共建共享、工作流服务沉淀、按需消费、生命周期管理、突破交互瓶颈。；展望：语义检索增强、跨团队知识联邦、知识质量自动评估、全异步工作流。；结尾重申：Skill、Agent、工具链会随模型迭代更新，但领域知识是永恒的。

### 带走三句话

1. 把知识拆成五层存储、五种类型、三级成熟度，让知识有清晰组织并可按需消费。
2. 知识库用独立 Git 仓库共建共享，贡献走暂存+异步合并，只有内容矛盾才人工裁决。
3. 让工作流在 INIT 注入、执行中按需查询、ARCHIVE 自动提取，每次交付都沉淀知识。
