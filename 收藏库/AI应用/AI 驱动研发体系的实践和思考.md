# AI 驱动研发体系的实践和思考

> 一句话定位：项目 Harness：知识、代码、规则、证据汇入 Git，让 AI 驱动研发闭环

## 摘要

团队用四个月把研发从 AI 辅助编程演进到 AI 驱动体系：业务 AI 研发的真正瓶颈是上下文而非模型能力，提出“本地优先：Agent + 文件夹 + Git”，把业务知识、代码、规则和验证证据装进同一 Git 工作空间。项目 Harness 分三层——AGENTS.md 定协议、skills 组织能力、scripts 执行门禁，以机器可读协议推进，人决策、Agent 执行。迭代本身就是知识飞轮，无需完美知识库；通用能力提升后 Harness 收缩，但知识治理与质量责任仍在，技术人走向 FDE。

## 要点

- 业务 AI 研发的真正瓶颈是上下文，而非模型能力。
- 本地优先：Agent + 文件夹 + Git，稳定上下文进 Git，动态事实经 MCP/CLI 实时查询。
- 公式演进：Agent = Model + Harness，业务研发 Agent 再叠加项目 Harness。
- 项目 Harness 分三层：AGENTS.md 定协议、skills 组织能力、scripts 执行确定性门禁。
- 迭代过程本身就是知识飞轮，无需完美知识库即可启动。
- 知识库分 wiki（业务知识）与 tech（技术上下文），不复制代码。
- 把一次迭代写成机器可读协议，以 REQ/AC/TC 建立需求承接与测试覆盖关系。
- 人负责决策、Agent 负责执行完整；未来技术人更接近 FDE。

## 提炼

> 一句话定位：项目 Harness：知识、代码、规则、证据汇入 Git，让 AI 驱动研发闭环

### 分节提炼

- **01 从辅助编程到 AI 驱动体系**：AI 辅助编程靠人在输入框给规则，新会话需重复输入；Coding Agent 能操作文件、代码、Git 和外部工具，从生成内容走向执行任务；通用 Harness 缺业务知识、流程约束与完成标准，需叠加项目 Harness；公式：业务 Agent = Model + 通用 Harness + 项目 Harness
- **02 核心思考**：上下文决定业务 AI 能走多远，模型只定通用能力；本地优先：稳定上下文进 Git，动态事实经 MCP/CLI 实时查询；老系统冷启动：关联代码资料、清洗 SKILL、钉钉采访补齐知识；迭代即知识飞轮；文件 Wiki 更新路径短，wiki/tech 分工且不复制代码
- **03 项目 Harness 结构**：目录树表达事实与执行边界，Agent 按同一结构检索并留证据；知识文件=正文+Metadata+链接+事实来源+Git 版本，source 说明出处；三层分离：AGENTS.md 协议、skills 能力、scripts 门禁；机器可读迭代协议贯穿 PRD/方案/测试/归档；人决策、Agent 执行
- **04 共性能力与业务协同**：复用已验证共性能力，业务团队保留贴合领域的项目 Harness；成熟实践沉淀为参考实现与可组合能力（流程 Skill、质量门禁）；统一工作项、代码、测试、发布间的数据协议与证据口径
- **05 结语：Harness 收缩**：文件搜索、Git、浏览器、多 Agent 协作等将成通用能力，项目 Harness 收缩；业务知识治理、项目规则、领域工具、验证标准与质量责任不会消失；技术人更接近 FDE：懂业务、设计规则、对端到端结果负责
- **06 团队介绍**：作者默达，来自淘天集团营销&交易技术团队，负责淘系价格力建设；Price360-KB 是团队在 AI 业务知识沉淀与交付中的实践之一

### 带走三句话

1. 业务 AI 研发的上限由上下文决定：把知识、代码、规则与证据装进 Git 工作空间，Agent 才能走远。
2. 不要等知识库完美再启动，在真实迭代中形成知识飞轮，让知识成为下一轮迭代的加速器。
3. 人守住决策与责任、Agent 执行完整；未来技术人需懂业务、设计规则并对端到端结果负责。
