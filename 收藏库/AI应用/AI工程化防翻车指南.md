# AI工程化防翻车指南

> 一句话定位：AI 工程化安全护栏：边界外置到 Harness，事前事中事后分层设防。

## 摘要

Agent 获得工具与执行权限后，风险放大。本文把安全边界外置到 Harness，以“永不信任，持续验证”为核心，按事前（隔离授权）、事中（循环封顶、人机分级、哨兵熔断）、事后（门禁审计自迭代）分层设防。工程侧失效（代码腐化、自我确认偏差、失控循环、上下文漂移）靠质量门、角色隔离与成本包络兜底；攻击面（注入、越狱）靠四层纵深防御加门禁拦截。文中以 10 阶段流水线为例，演示需求到投产各环节如何命中护栏，并配套规则注入、Subagent 隔离、精确回退、Dry Run，收敛为 10 条可迁移原则。

## 要点

- Agent 权限越大风险越高，Harness 既是执行层也是安全边界。
- 核心逻辑是 Never Trust, Always Verify，靠纵深防御与运行时安全落地。
- 事前锁攻击面：系统隔离、工具白名单与最小权限、输入净化与 I/O 脱敏。
- 事中控跑偏：pre-dispatch 授权、成本包络封顶、HITL 三色卡、哨兵与熔断。
- 事后兜底：硬软门禁互补，准入 AND、策略即代码、全链路审计、自迭代。
- 工程侧失效与攻击面两类风险合起来才是完整清单。
- 以 10 阶段流水线演示护栏命中，失败精确回退，Dry Run 先修 Harness。
- 安全边界设在模型改不动的地方，软约束提合规率、硬约束兜底。

## 提炼

> 一句话定位：AI 工程化安全护栏：边界外置到 Harness，事前事中事后分层设防。

### 分节提炼

- **01 问题与动机**：Harness 连接模型、工具与执行环境，决定攻击面与损失上限。；工程侧失效：代码腐化、自我确认偏差、失控循环、上下文漂移。；攻击面：注入 vs 越狱、DPI vs IPI，进入 Agent Loop 后升级为系统安全问题。；护栏要把“禁止做的”边界落到机制上，而非只写进提示词。
- **02 核心思想**：Never Trust, Always Verify：默认不信任任何输入、中间产物与工具调用。；纵深防御层层设卡，运行时安全持续监控、动态拦截与降级。；Model + Harness = Agent，Harness 是一等治理对象，换模型须连 Harness 重评。；边界设在模型改不动的地方：网络、会话、系统层等执行点。
- **03 纵深防御**：事前防：系统隔离、工具白名单与最小权限、输入净化与 I/O 脱敏。；事中控：pre-dispatch 授权、成本包络、HITL 三色卡、哨兵与熔断。；事后兜：硬门禁拦“确定错的”，软门禁捕“可能差的”，审计加自迭代。
- **04 配套机制**：状态纠偏回滚：持续打快照，污染时回滚到最近安全检查点。；全链路审计记录完整执行轨迹，落盘前必须脱敏。；自迭代把观测与评测沉淀为规约与门禁调整。
- **05 研发流水线**：10 阶段流水线每阶段命中对应护栏，失败精确回退到责任阶段。；规则注入是软约束，沙箱、白名单通道与 CI 门禁才是硬兜底。；Subagent 隔离按利益冲突、信任边界、上下文健康三信号触发。；Dry Run 用虚拟需求空跑验证 Harness 本身，提前修门禁与回退映射。
- **06 小结**：收敛为 10 条可迁移原则：边界外置、持续验证、按声明授权、分级拦人、写评拆开等。；安全边界放在模型外，由确定性、模型改不了的 Harness 执行。
- **07 附录**：全景总图从纵向层次与横向“问题→对策→实现”归类所有护栏。；同一批护栏可按时序（事前/事中/事后）三泳道归类。

### 带走三句话

1. 写和评必须拆开：同一个 Agent 既写又评，几乎必然放水。
2. 参数写错就不可逆的动作，合法性交给确定性代码把关，缺省即拒。
3. 护栏本身也要被验证：Dry Run 空跑加 policy-as-code 单测持续把关。
