# 从OpenClaw，怎么走到了Super Agent？

> 一句话定位：用一条「Bot ↔ Working Agent 互相靠拢」的演进线，解释 Super Agent 背后真正在解决的是什么。

## 摘要

作者 spike（腾讯游戏数据团队负责人）回顾过去一年 Agent 产品的演进：年初以 OpenClaw 为代表的 Bot（聊天入口），到 4–5 月 WorkBuddy 等 Working Agent（IDE/桌面环境），再到最近两类产品互相靠拢——Bot 补工作台/文件/连接器，Working Agent 补手机与 channel 入口。背后是两条朴素需求：Agent 要做好事，必须更接近人的实际工作环境；用顺之后，人希望随时能找到它、把能力交给别人用。文章进一步指出：Agent 做不好往往不是 Prompt 没写清，而是 Context（背景）与 Harness（执行安排）没接好；工作环境本身可以交给 Agent 参与建设（Mods、DeepSeek Harness 的 Creator mode）；成熟 Agent 可以 Coach 新 Agent（先做例子、回来源核对、让人只判断真正有分歧处）。最终 Bot 与 Working Agent 在接近同一个问题——什么样的 Agent 能在具体事情上越来越准确地代表人做事。

## 要点

- 产品演进两条路：Bot 补工作台/文件/连接器，Working Agent 补手机/channel 入口；背后是「接近真实工作环境」+「随时可用、可共享」两个朴素需求。
- 换入口不等于上下文自动同步：使用者要的是「同一件事能继续」，不是每换一个地方就认识一个新助手。
- Context 与 Harness 才是关键：Agent 做不好，不一定是 Prompt 没写清楚，可能是读不到资料、拿了旧版本、工具没接好；只加一句「你要认真一点」通常没用。
- 环境建设交给 Agent：Mods 让用户/Agent 修改提示、工具与界面；DeepSeek Harness 的 Creator mode 支持通过对话创建插件、扩展工具/Skill/界面。
- 成熟 Agent 可以带新 Agent：先用顺的 Agent 做几个例子、回来源核对、帮它调整，人只看真正有分歧的判断。
- Coach 要防两个坑：不能老 Agent 替新 Agent 干完还宣布「教会了」；给别人用时不能复制整份私人记忆，也不能默认自己的偏好适合所有使用者。

## 提炼

> 一句话定位：复盘 Agent 产品一年演进：从 Bot 走向 Super Agent。

### 分节提炼

**先看一个趋势，以及背后的朴素逻辑**

- 年初产品多为 Bot，便于新手从聊天工具找到 Agent；4、5 月起 IDE/桌面 App 类 Working Agent 增多，竞争激烈。
- 近期 Bot 与 Working Agent 互相补对方能力，双向靠拢。
- 驱动变化的两条需求：贴近真实工作环境；随时找到、能力可复用。

**从容易用起来 到真正用起来**

- 找到 Agent 容易，把活干好难，背景与资源直接影响结果。
- IDE/工作台让背景留在同一环境，减少反复交代；要看工作在哪发生、Agent 能否拿到相关背景并继续做。
- 按权限找到内容并接上变化，比存得多更重要。
- 易错：只给一句任务描述，模型读不到背景与口径，产出差别大；给 Agent 云端电脑≠已和你在同一工作环境。

**越好用，越希望随时能找到它**

- Agent 用顺后，人希望离开电脑也能继续用。
- 此时回到 Bot 不是遥控器，而是让新讨论回到原工作；入口方便会提升背景积累质量。
- 易错：换入口不等于上下文自动同步，否则每处都像新助手。

**从自己用 到和别人一起用**

- 把建设好的 Agent 能力交给别人用，而非只分享 Prompt；专业同学维护知识工具，使用者带业务问题参与判断。
- Bot/群聊适合联系交流，但背后仍需人维护专业能力；关键是能力能被找到、被使用，反馈能回到维护者。
- 易错：群里多一个头像，不会自动解决维护与执行环境问题。

**工作环境本身，也可以让Agent参与一起建设**

- Context 是可取得背景，Harness 是让模型实际工作的安排；做不好不一定怪 Prompt，可能读不到资料或工具没接好。
- 先看实际过程，再决定补背景、改说明还是调工具；Mods 与 Creator mode 让用户和 Agent 一起改造环境。
- 易错：只加「你要认真一点」解决不了问题；插件程序要看来源/权限/可恢复版本，涉账号外发付费不能省确认。

**用顺的Agent 还可以帮忙带一个新的**

- 成熟 Agent 可先做例子再 Coach 新 Agent，人只裁决分歧；新 Agent 常见问题：把已记录当已接手、拿旧信息提醒、只列事实。
- 不能让老 Agent 代做后宣布教会，要让新 Agent 自己练；共享给他人时分开专业能力与私人资料。

**不同的产品 正在接近同一个问题**

- Bot 与 Working Agent 殊途同归，都在补环境和延伸入口；Dots、Grok Bot、Muse 从不同背景回应同一问题。
- 目标：Agent 在具体事情上越来越准确代表我做事；先在具体事上可靠、能纠正，再扩大范围更实际。
- 易错：只记很多信息≠理解取舍；只知道喜好没有工具也做不了事；不该越来越顺着说，应提醒判断可能已不适合现在。

### 知识卡（精选）

1. 概念对比｜Bot vs Working Agent：Bot 联系便捷、新手易上手；Working Agent 贴近工作环境、能执行。近期二者互相补对方能力。
2. 概念对比｜Context vs Harness：Context 是做事时可取得的背景；Harness 是让模型实际工作的安排（工具、记忆、执行与纠错）。
3. 概念对比｜分享 Prompt vs 开放能力：分享 Prompt 只传递一段话；开放能力是把维护好的知识、工具与处理方法交给别人先用起来。
4. 结论｜找到 Agent ≠ 把活干好：需求背景、数据口径、历史分析与可用工具直接影响产出，不只是模型能力。
5. 结论｜工作在哪里发生决定背景接不接得上：要看实际工作在哪里发生、Agent 能否拿到相关背景并继续做下去，而不是只看聊天窗口。
6. 结论｜入口方便会提升积累质量：越容易继续聊，越愿意把变化和未整理的想法交给 Agent，背景越积累它越理解人。
7. 数据｜4、5 月增速分化：4、5 月份，多数 Bot 类产品用户增速低于 WorkBuddy 这样的 Working Agent 产品。
8. 易错点｜只加「认真一点」无效：做不好常因读不到资料、拿到旧版本或工具没接好，加一句「认真」解决不了。
9. 易错点｜代做≠教会：不能让老 Agent 替新 Agent 完成再宣布教会，要换例子、换会话让新 Agent 自己做。
10. 易错点｜共享时别复制私人记忆：共享能力时不要把整份私人记忆复制出去，也别默认自己的偏好适合所有使用者。
11. 结论｜产品在接近同一问题：需要 Agent 在具体事情上越来越准确代表我：懂取舍、有工具权限、接得上变化、能纠正。
12. 易错点｜AI 帮装不能省确认：插件程序要看来源、权限与可恢复版本，涉账号、外发或付费不能因「AI 帮我装的」省掉确认。

### 带走三句话

1. Agent 产品演进由两条需求驱动：贴近真实工作环境，以及随时找到、能力可复用。
2. Agent 做不好先查背景与工具（Context/Harness），而不是只加 Prompt 规则。
3. 能力建设本身正在 Agent 化：改环境、带新 Agent，人只裁决关键分歧。
