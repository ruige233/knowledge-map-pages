# 作为开发者，我如何提高任务型大模型应用的响应性能

> 一句话定位：分享提升任务型大模型应用响应性能的四个实用方法

## 摘要

本文基于行程规划等实际场景，分享提升任务型大模型应用响应性能的四个思路。一是在 prompt 中约束输出结构、配合 few shot，去掉空格换行等冗余，输出 token 从 122 降到 33，直接缩短响应时间。二是分解任务、大小模型分工：qwen-plus 规划地点与计划，qwen-turbo 异步生成一句话介绍，测试中 turbo 输出更多 token 仍快约 0.4 秒，且要避免分工内容冲突。三是流式输出，边接收边正则提取地名，异步并发查 poi、生成介绍，按 seq 立即回传客户端。四是约定短代号映射长结果，借鉴 protobuf 思想，只输出序号或 y/n，本地解析全称。核心理念：减少输出 token、选对模型尺寸、采用流式输出。

## 要点

- 全文响应时间与输出 token 数量正相关，减少输出 token 是提升响应性能最直接的方式之一。
- 在 prompt 中约束输出结构并配合 few shot，可去除空格换行等冗余字符，大幅压缩输出 token。
- 分解任务、大小模型分工：复杂规划用 qwen-plus，简单介绍用 qwen-turbo，异步执行不阻塞主线。
- 分工前提是不能产生前后内容冲突，游玩计划与当天行程地点须由同一模型输出以保证一致。
- 流式输出时边接收边用正则即时提取地名，异步/并发查询 poi 接口并生成介绍，按 seq 立即返回客户端。
- 提前约定短代号映射长结果，借鉴 protobuf 思想，让模型只输出序号或 y/n，本地解析全称。
- 核心理念：减少输出 token、选择合适尺寸的模型、采用流式输出。

## 提炼

> 一句话定位：分享提升任务型大模型应用响应性能的四个实用方法

### 分节提炼

- **01 背景与场景案例**：任务型应用指完成预约、规划等特定任务，交互偏结构化，要求输出结构化数据以便后续处理。；大模型存在速度、效果、功能的不可能三角，需在保证效果前提下提升响应速度。；四个结论：约束输出结构、分解任务分工、流式输出、短代号映射长结果。；行程规划场景中，大模型负责地点与计划，poi 与行驶距离时间由外部 API 获取。
- **02 四个优化思路详解**：思路1：prompt 约束结构加 few shot，去掉空格换行等冗余，输出 token 可从 122 降到 33。；思路2：qwen-plus 规划、qwen-turbo 生成介绍，异步执行；测试 turbo 输出更多 token 仍快约 0.4 秒。；思路3：流式输出边收边正则提取地名，异步并发查 poi、生成介绍，按 seq 立即回传。；思路4：用序号或 y/n 短代号替代中文 key，本地映射全称，少输出即可得完整结果。
- **03 总结**：核心理念：减少输出 token、选择合适尺寸的模型、采用流式输出。；四个方法具有广泛适用性，可迁移到多种任务型场景。

### 带走三句话

1. 先在 prompt 里约束输出结构，减少空格换行等冗余，用更少 token 装更多信息。
2. 把任务拆开，复杂规划用大模型、简单介绍用小模型异步做，前提是内容不冲突。
3. 采用流式输出边收边处理，并用短代号映射长结果，减少等待和输出量。
