# 为什么AI干得总是差点意思？教你怎么把需求一次说清楚

> 一句话定位：把提示词工程从概念到最佳实践的系统性梳理。

## 摘要

本文系统梳理提示词工程：先点明大语言模型本质是「预测下一个 token」的预测引擎，提示词工程就是通过优化输入引导模型输出的系统方法，包含质量、稳定性、正确性三个维度，且有明确局限。随后讲解 System/User/Assistant 三种角色与 System Prompt 和 User Prompt 的区别，介绍输出长度、temperature、top_p 等关键参数。主体部分给出六种提示词表达格式（自然语言、Markdown、XML、伪代码、JSON、Jinja）、四部分提示词框架（角色/背景/任务/约束），以及最佳实践：清晰直接详细、提供示例（few-shot）、让 JSON 输出稳定、设定角色、用 XML 标签区分内容单元，再到引导模型思考（CoT）、提示词链、设定执行步骤与提示词防护。结论：好提示词 = 结构化清晰 + 足够上下文，本质是用 AI 能听懂的方式把意图说清楚。

## 要点

- LLM 本质是预测引擎：给定上下文，逐步预测「下一个最合理的 token」，每一步生成都依赖前文。
- 提示词工程三维度：质量（说到点子上）、稳定性（靠得住）、正确性（说得对）；它只能在模型已有能力内推高成功概率。
- 三种消息角色：System（人设/规则，开发预设）、User（当次需求）、Assistant（回复）；系统提示词与用户提示词共同影响响应。
- 关键参数：输出长度只截断不「写更简洁」；temperature 控制采样随机性（=0 为贪婪解码）；top_p 为核采样，与 temperature 相互影响不宜同调。
- 表达格式：自然语言 / Markdown / XML / 伪代码 / JSON / Jinja，按任务复杂度选择或组合，核心是结构化、无歧义。
- 最佳实践：先「把任务说清楚、给足上下文」→ 用最好模型 → 再用技巧；四部分框架（角色/背景/任务/约束）；few-shot 示例；强约束稳定 JSON；角色设定；XML 标签分隔；CoT；提示词链拆步；警惕诱导式提示词。

## 提炼

- one_liner：一套把任务讲清、靠结构降歧义的提示词工程实用方法
- 各节要点：
  - 01 LLM 本质：海量数据训练的预测引擎，每次生成一个 token 再继续预测，逐步依赖前文上下文。
  - 02 提示词工程：系统性优化输入以提升输出质量；三维度=质量（专业完整有价值）/稳定性（跨场景一致）/正确性（准确可信）；只能推高成功概率，不能突破模型能力上限。
  - 03 受众：使用 AI 工具的人 + 制造 AI 工具的人；AI 应用角度=User Prompt 在 System Prompt 约束下生成回复，产品角度=用产品设计规定使用与响应方式。
  - 04 角色：System（预设人设/规则/风格，用户不可见）、User（当次需求）、Assistant（回复）；系统提示词设人设与回复逻辑，用户提示词表达当次问题。
  - 05 参数：输出长度只限 token 数量、不会「写更简洁」；temperature 越低越确定（0=贪婪解码）；top_p 核采样，与 temperature 相互影响不宜同调。
  - 06 好提示词顺序：先讲清任务给足上下文 → 用最好的模型 → 再用提示词技巧。
  - 07 表达方式：自然语言/Markdown/XML/伪代码/JSON/Jinja；核心是结构化表达、明确边界、避免歧义。
  - 08 框架：角色/背景信息/任务/约束四部分，核心是引导一次性把话说完说清楚。
  - 09 最佳实践：清晰直接详细（把模型当聪明新员工）；提供示例（One-shot/Few-shot，示例要相关/多样/清晰）；稳定 JSON 三招（结构模板+禁输出模板外文字+强约束语言）；设定角色（提升准确/贴合语气/改进专注）；XML 标签区分内容单元。
  - 10 CoT：让模型先思考再回答，可加「一步步思考」/规定步骤/标签区分分析与结果；推理模型额外加 CoT 未必有改善。
  - 11 提示词链：复杂任务拆多步、上一步输出做下一步输入；优点准确/清晰/易调试，缺点耗时更多。
  - 12 执行步骤：把先做什么后做什么写清楚；计算任务要提供完整已知条件并核对过程与单位。
  - 13 防护：诱导式提示词借角色扮演、情绪引导诱使模型输出敏感信息，需防护。
  - 14 总结：好提示词=结构化清晰+足够上下文；本质是用 AI 能听懂的语言沟通；上下文工程可通过 RAG、工具调用、技能获取信息。
- 带走三句话：
  - 先讲清任务、给足上下文，再用好模型，最后才谈提示词技巧。
  - 提示词工程本质是沟通：用结构化表达消除歧义，让 AI 听懂意图。
  - 复杂任务拆步骤、给示例、设角色、定约束，能显著提升稳定性与准确性。
