# Agent 评测具体怎么做？学习淘宝、货拉拉和阿里云的实践（万字）

> 一句话定位：三篇一线实践拆解 Agent 评测——同时盯业务结果与执行过程，用规则+模型+人工校准把评测做成发布门禁。

## 摘要

文章汇总淘宝、货拉拉、阿里云三篇 Agent 评测实践，核心观点：Agent 评测必须同时看「业务结果」和「执行过程」——每一轮调用看起来合理，任务未必完成；工具返回成功，业务结果也未必符合要求。淘宝：线上日级批量评测，六层框架（CTX 上下文门控 / OOSR 越界拒答 / OOC 能力边界 / TCC 工具执行 / CNT 内容文本 / RED 安全红线）分层定位失败，重点处理样本分母、证据清洗、Judge 输入质量，并逐条比对人工与 Judge 的判定和归因。货拉拉：业务评测平台，调用链拓扑 + 适配器统一接入异构 Agent，用例前置校验，规则引擎与 LLM-as-a-Judge 分工，多次评分离群过滤，Session 级判定（严重违规一票否决），SSE 压测（TTFT/TTLT/TPS/RPS/P99）与 CI/CD 发布门禁。阿里云：Skill 与 Agent 分层评测，STA 行为覆盖率（已覆盖行为数 ÷ 需测行为数），可执行可核验用例（JSON Schema + prepare/track/state_checks/destruct），AgentLoop Trace 支撑四维判定（完成度/忠实度/事实一致性/过程正确性），安全违规综合分归零、环境可重入、黄金集 + 线上回归七日基线发布检查。

## 要点

- 评测要同时查「业务结果」与「执行过程」：每一轮调用合理 ≠ 任务完成；工具返回成功 ≠ 业务结果符合要求。
- 淘宝六层框架（CTX/OOSR/OOC/TCC/CNT/RED）分层定位失败位置；但「失败在哪一层」≠「该改哪里」——可能修数据清洗、prompt、Rubric 或 Agent。
- 样本分母决定指标可信度：路由准确率的分母必须含「本该进入却未进入」的请求；意图标签误标会直接污染评测分母。
- Judge 输入质量是误判重灾区：工具提示词被当成回复、字段解析为空、状态枚举无语义映射、多轮证据用错（前轮金额、缺提问时间戳）。
- 人工与 Judge 通过率一致也可能存在大量分歧：要逐条比对判定与归因，不能只比通过率；HASH 抽样可复现但需明确抽样单位。
- 货拉拉：用例前置校验（不合规不创建 Job）、规则引擎与模型裁判分层分工、多次评分离群过滤 + 方差阈值送人工、Session 级判定 + 严重违规一票否决。
- 阿里云：STA=已覆盖行为数÷需测行为数；用例需可执行、可核验（Schema + prepare/track/state_checks/destruct）；四维判定（完成度/忠实度/事实一致性/过程正确性）；安全违规综合分归零；环境可重入；黄金集全过 + 综合分不低于线上回归七日均值才发布。

## 提炼

> 一句话定位：对比淘宝、货拉拉、阿里云 Agent 评测实践：样本、规则与复核三套打法。

### 分节提炼

**一、淘宝AI购物助手在线评测落地实践**

- 日级批量评测走五步：采集、清洗、LLM 推理、结果解析聚合、人工校验。
- 路由准确率分母须含本该进该 skill 却未进的请求，否则漏判路由失败。
- 评测输入先清洗：去工具透传提示词、修字段解析、补业务状态语义映射。
- 推理后 Check 节点对账输入输出条数，阻断丢失、重复与空结果后再统计。
- 六层框架 CTX/OOSR/OOC/TCC/CNT/RED 分层定位失败位置，RED 独立查安全。
- 证据按轮次隔离：只传当前轮 tool_calls，补提问时间戳，先摘录证据再判定。
- 人工与 Judge 逐条比对判定和归因，不能只比通过率；失败层不等于根因。
- 易错：路由通过率下降先查分母；工具返回透传系统提示词被 Judge 误当回复。

**二、货拉拉业务 Agent 评测平台的工程实践与深度思考**

- 单看一轮合理不够，需同时检查业务结果和执行过程，并记录上下游调用关系。
- 用例创建前批量校验字段、类型、枚举与测试标识，不合规不启动 Job。
- 规则引擎管确定性校验，裁判模型管语义，按问题类型分工。
- 裁判多次评分、离群过滤、加权均值，方差超阈值交人工复核。
- Session 级判定：严重违规一票否决或总分封顶，不被其他轮高分抵消。
- SSE 压测记 TTFT/TTLT/TPS/RPS/P99，支持固定、阶梯与线性爬坡。
- 评测接入 CI/CD：冒烟先行，全量基准不达 purposeScore 即 FAIL 阻断发布。
- 易错：用例不合规就启动会消耗 token 并产生真实操作；简单平均掩盖严重违规。

**三、从 Skill 到 Agent：评测技术的路径与实践**

- Skill 评行为与异常分支，Agent 还需查组合调用、状态传递与端到端结果。
- 执行过程设检查点：对象匹配、变更受控、恢复有效，回查真实资源。
- STA=已覆盖行为÷需测试行为，从 Skill 文件提取行为清单再对账用例。
- 用例用 JSON Schema 定义，配 prepare/track/state_checks/destruct 可执行可核验。
- 来源工单 60%+专家 30%+知识库 5%+对抗 5%，按 FMEA 概率×严重×难检分级。
- AgentLoop Trace 对照 API、参数与顺序，四维判完成/忠实/事实/过程。
- 安全违规综合分归零一票否决；证据不足标待核验，不猜不误判。
- 环境可重入：每轮重置资源与人工确认，黄金集全过且不低于七日基线才发布。
- 易错：只数用例不查行为覆盖；不清理旧产物会误导恢复成功。

### 知识卡（精选）

1. 概念对比｜执行成功≠业务完成：工具返回成功≠用户要的业务结果达成，三家都要求核对真实资源与最终产物。
2. 结论｜六层框架分层定位：CTX/OOSR/OOC/TCC/CNT/RED，一层失败后续串行跳过，RED 仍独立检查。
3. 易错点｜分母选错样本：投诉标签混入功能咨询会拉低路由通过率。
4. 易错点｜工具提示词当回复：工具返回透传系统提示词，Judge 误当 Agent 回复。
5. 易错点｜条数相同≠样本有效：漏一条写两次或评分字段为空，需唯一标识对账。
6. 数据｜样本量估算：95% 置信、50% 保守比例、±1pp 约 9604 条。
7. 代码模式｜拦截器三时机：TASK_BEFORE / SESSION_BEFORE / REQUEST_BEFORE 注入参数。
8. 概念对比｜规则与模型分工：规则做结构化/正则/硬匹配/关键词/语义相似度，模型管语义。
9. 易错点｜相似度高≠事实正确：「可以退款」与「不可以退款」结论相反。
10. 结论｜严重违规单独处理：任意一轮泄露/越权写/违规承诺即会话不通过或封顶。
11. 代码模式｜可核验用例 Schema：JSON 用例 + prepare/track/state_checks/destruct。
12. 概念对比｜覆盖≠通过：STA 衡量充分性，行为是否符合要求另判。
13. 结论｜安全违规综合分归零：OpenAgent 一票否决，不可用高分补偿。
14. 数据｜货拉拉平台规模：114 Agent、16337 黄金用例、11063 功能评测、669 前置拦截缺陷。

### 带走三句话

1. 先核样本分母与证据清洗再算指标；失败标签只定位位置，根因另查数据/prompt/Rubric/Agent。
2. 确定性规则与模型裁判按问题类型分工，严重违规单独一票否决，争议样本交人工复核。
3. 用例必须可执行、可核验、可重入：覆盖用行为对账，验收回查真实资源，发布靠回归门禁。
