# 维护3.3万字符的长Prompt？让优化Agent迭代执行Agent

> 一句话定位：用 harness² 的 INV/DOM 双路提案 + 依证据合成，让优化 agent 自动迭代一份 3.3 万字符的打标长 Prompt，单轮把问题识别 F1 从 82.78% 提到 89.89%。

## 摘要

腾讯输入法联想场景的工程实践（原创作者：徐泓镔）。优化对象是一个 LLM 打标节点背后的存量 Prompt——超过 3.3 万字符、由历史规则逐步累积而成，用来自动判断联想候选的连贯性并与人工标注对比算准召。此前已基于 Skill 做过自我迭代闭环：agent 读失分样本、改 Prompt、重跑评测，流程能跑通，但连续 5 个版本准召都没显著提升。复盘结论是：瓶颈不在"有没有闭环"，而在"闭环里的改进没有被组织"——同一 agent 同时改输出格式、规则冲突、缺失判例这些性质不同的问题，改动没有边界，收益与回退都无从归因。于是引入 Google Research 开源的 harness²（Recursive Agent Harnessing）：把改进拆成 INV（怎么工作：格式、规则冲突、流程）和 DOM（需要知道什么：规则、例外、判例）两路互不可见的并行提案，各自全量探测留下行为证据，再由合成 agent 依证据合并，最后按问题识别 F1 与阈值决定是否采纳，并把有证据支撑的经验写进可选择性复用的经验库（任务级递归 + harness 级递归两层）。落地关键是不改框架本体、在外层加约 2400 行适配层：把 8 个可编辑组件收窄到实际生效的 Prompt 与少量脚本；常驻内容上限从 24000 放宽到 50000 字符以容纳存量长 Prompt；重写执行环节（并发打标 611 条全量评测，替代沙箱 agent 轨迹）；最核心的是把"有真值"这件事改造好——把汇总指标（准召 F1 + 因格式被丢弃的记录数）和带模型判断依据的分歧样本一起交给优化 agent，用指标 + 阈值取代无法访问真值的官方 selector，并加机械校验防止把评测样本原文写进 Prompt 造假。结果：611 条数据跑 1 轮、约 95 分钟、无人工介入，问题识别准确率 78.84%→87.43%、召回率 87.13%→92.49%、F1 82.78%→89.89%（+7.11pp）；INV 主要提召回、DOM 主要提准确率（但因格式问题丢弃 37 条记录，提升含虚高），合成后两路收益叠加且未损害其他类别（整体一致性 97.71%→98.60%）。

## 要点

- 瓶颈诊断要先于换工具：旧 Skill 闭环 5 轮无效，不是因为闭环不完整，而是因为改进没有组织结构——改动无边界 → 收益无法归因 → 无法累积。
- `Agent = Model + Harness`：表现不只取决于模型，还取决于系统提示词、记忆、技能、工具说明、脚本、子 agent 编排；harness² 把这套 harness 拆成 8 个可编辑组件（运行时各对应一个文件）。
- 两层递归：任务级递归（base → Propose → Probe → Compose，改进当前任务的 harness）+ harness 级递归（反思 agent 把有行为证据支撑的经验写进经验库，后续任务按需检索复用，而非自动继承）。
- Propose 的视角拆分是效果来源：INV 只看 workflow（输出格式、规则冲突与优先级、措辞位置），DOM 只看领域知识（规则、例外、判例）；两路互不可见，各自 Probe 一次留证据，Compose 再依证据合并而非凭"预期指标会提升"。
- Probe 的行为对比只算证据、不算正确性验证；selector 无法访问真值时，用一个带证据的合成 agent 替代单纯的自动择优。
- 适配 >> 魔改：不改框架本体，外层加约 2400 行适配层，仅在运行时覆盖与"无真值"相关的通用声明。
- 长 Prompt 三条硬约束（务必写进优化 agent 的任务说明）：限定并机械校验可编辑范围（改了别的文件直接拒绝并回传原因）；禁止"整洁式"大幅重写（否则历史上修 bug 加的规则会失效）；规则冲突时明确优先级与例外，而不是删掉其中一条；不得改输出结构。
- 常驻内容上限 24000→50000 字符：框架的这个上限本来是防膨胀，但存量 Prompt 本身就是 3.3 万字符的系统提示词，必须先放开才有改动空间。
- 执行环节要按任务形态重写：harness² 默认"agent 在沙箱跑长任务收轨迹"，这里是"611 条数据并发打标 + 解析 diff + 算指标"，产出是逐条预测而非轨迹；并设全局并发上限 + 少量数据冒烟测试，大面积失败立即中止。
- 有真值时的四件改造：①把真值与指标（含被丢弃记录数）纳入执行证据；②给优化 agent 写专用任务说明（评测口径 / 工作方法 / 约束与节奏）；③按 F1 + 阈值在 base、inv1、dom1、agg1 里择优采纳，不用无法访问真值的官方 selector；④机械校验拦截过拟合（保护原示例不许删改、新示例不得与评测集样本完全一致）。
- 隐藏评分口径必须写明：输出格式异常的记录会被整条丢弃且不参与评分——不告诉优化 agent，它就不会去修格式，而格式恰恰是丢分大户。
- 单轮成本可算：4 次全量执行（约 2400 次打标调用）+ 4 次优化 agent 调用（INV、DOM、合成、反思），单次优化调用 10–20 分钟；`--continue` 以采纳版本为新基线继续下一轮。
- 一个真实的好 bug：Prompt 正文禁止代码块围栏，内置输出样例却带围栏，模型模仿样例 → 合法 JSON 解析失败 → 整条丢弃。这是"工作方式"类失分，只能由 INV 路径发现。
- 评估不能只看主指标：dom1 准确率最高（89.24%），但格式问题导致丢弃 37 条记录、召回率仅 88.68%，部分收益是虚高；每版都要同时看有效样本数与其他类别指标。

## 提炼

- one_liner：让优化 agent 迭代执行 agent，自动改写 3.3 万字符打标长 Prompt
- 各节要点：
  - 背景（长 Prompt 与旧闭环）：优化对象是一份由历史规则累积而成、超过 3.3 万字符的打标 Prompt；问题样本仅约 6%，但直接影响体验，核心看问题识别的准召与 F1；此前 Skill 闭环能跑通，但同一 agent 同改格式、规则冲突与判例，5 版无显著提升｜易错点：只给"提升准确率和召回率"的笼统目标，改动无边界，收益与回退的来源无法定位
  - 过程与方法（harness² 与真值适配）：harness² 将 harness 拆为 8 个可编辑组件，分任务级递归与 harness 级递归两层；任务级为 base、Propose（INV/DOM 两路互不可见）、Probe、Compose，k 控制探索宽度；不改框架本体，外层加约 2400 行适配层，常驻内容上限 24000→50000 字符；有真值时把汇总指标与带模型判断依据的分歧样本交给优化 agent，并按 F1 阈值采纳｜易错点：可编辑范围过宽会让优化 agent 改动不影响执行结果的文件；面对长 Prompt 出于"整洁"大幅重写会使历史修复规则失效；agent 长时间只推理不改文件会被上游中断、整轮改动被丢弃
  - 成效（单轮 F1 +7.11pp）：agg1 准确率 78.84%→87.43%、召回率 87.13%→92.49%、F1 82.78%→89.89%；inv1 只把召回率提到 90.17%，无输出记录 6→0、数量不符 6→1；dom1 准确率升至 89.24% 但丢弃 37 条记录，提升含虚高；一致性 97.71%→98.60%，正常类 F1 98.78%→99.25%，未以损害其他类别为代价｜易错点：只看主指标会误判——dom1 准确率最高，却因格式问题丢弃 37 条记录
  - 经验总结（五条经验）：改进需要有组织：分视角提案、分别验证、依证据合并，仅形成闭环不够；引入框架借鉴方法不照搬形态，在外层适配并逐项检查默认约束是否适用；有可靠评估信号就完整交给优化 agent，含"格式异常整条丢弃"这类隐含评分口径；经验库只沉淀有证据支撑、可迁移的经验，后续按需检索而非自动继承｜易错点：允许对存量长 Prompt 大幅重写，会让历史修复规则失效
- 带走三句话：
  - 让同一 agent 兼改格式、规则与判例，改动无边界就无从归因；拆成 INV/DOM 分视角提案、各自验证再依证据合成，单轮即可见效。
  - 既然有真值，就把汇总指标和带模型判断依据的分歧样本完整交给优化 agent，再用指标阈值与机械校验决定采纳。
  - 引入框架要借鉴方法而非照搬形态：不改框架本体、在外层做适配，同时禁绝"整洁式重写"与只看主指标的评估。
